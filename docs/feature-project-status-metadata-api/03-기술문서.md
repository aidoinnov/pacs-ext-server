# 프로젝트 상태 메타데이터 API 기술 문서

## 📋 개요

본 문서는 프로젝트 상태 관리 시스템의 메타데이터 API 및 관련 기능에 대한 기술적 세부사항을 설명합니다.

**주요 기능**:
1. 프로젝트 상태 메타데이터 API (`GET /api/projects/meta`)
2. 프로젝트 상태 enum 리팩토링
3. 통합 테스트 및 E2E 테스트
4. API 점검 대시보드

## 📊 데이터 모델

### ProjectStatus Enum

```rust
#[derive(Debug, Clone, Copy, Serialize, Deserialize, Type, PartialEq, Eq)]
#[sqlx(type_name = "project_status", rename_all = "SCREAMING_SNAKE_CASE")]
pub enum ProjectStatus {
    Preparing,      // → PREPARING
    InProgress,     // → IN_PROGRESS
    Completed,      // → COMPLETED
    OnHold,         // → ON_HOLD
    Cancelled,      // → CANCELLED
}
```

**데이터베이스 매핑**:
- PostgreSQL ENUM 타입: `project_status`
- `rename_all = "SCREAMING_SNAKE_CASE"` 속성으로 자동 변환
- 카멜케이스 → 언더스코어 변환 (예: `InProgress` → `IN_PROGRESS`)

### 메타데이터 DTO

```rust
/// 프로젝트 상태 메타데이터
pub struct ProjectStatusMeta {
    pub value: String,        // "IN_PROGRESS"
    pub label: String,        // "진행중"
    pub description: String,  // "프로젝트가 활발히 진행 중"
}

/// 프로젝트 메타데이터 응답
pub struct ProjectMetaResponse {
    pub available_statuses: Vec<ProjectStatusMeta>,
}
```

**특징**:

**사용 예시**:
```rust
for status in ProjectStatus::all() {
```

```rust
pub const fn as_str(&self) -> &'static str {
    match self {
```

### 2. 메타데이터 API

#### 2.1 엔드포인트

```
GET /api/projects/meta
```

**응답 예시**:

```json
    },
    {
      "value": "IN_PROGRESS",
      "label": "진행중",
      "description": "프로젝트가 활발히 진행 중"
    },
    {
      "value": "COMPLETED",
      "label": "완료",
      "description": "프로젝트가 성공적으로 완료됨"
    },
    {
      "value": "ON_HOLD",
      "label": "보류",
      "description": "프로젝트가 일시적으로 중단됨"
    },
    {
      "value": "CANCELLED",
      "label": "취소",
      "description": "프로젝트가 취소됨"
    }
  ]
}
```

#### 2.2 구현 로직

```rust
pub fn get_project_metadata(&self) -> ProjectMetaResponse {
    let available_statuses = ProjectStatus::all()
        .iter()
        .map(|status| ProjectStatusMeta {
            value: status.as_str().to_string(),
            label: status.label().to_string(),
            description: status.description().to_string(),
        })
        .collect();

    ProjectMetaResponse {
        available_statuses,
    }
}
```

**처리 흐름**:
1. `ProjectStatus::all()` - 모든 상태 가져오기
2. `.iter()` - 반복자 생성
3. `.map()` - 각 상태를 `ProjectStatusMeta`로 변환
4. `.collect()` - `Vec<ProjectStatusMeta>` 생성
5. `ProjectMetaResponse` 반환

**시간 복잡도**: O(n), n=5 (상태 개수)  
**공간 복잡도**: O(n)

### 3. 라우팅 순서

#### 3.1 문제 상황

```rust
// ❌ 잘못된 순서
.route("/projects/{project_id}", web::get().to(get_project::<P>))
.route("/projects/meta", web::get().to(get_project_metadata::<P>))
```

**결과**:
```
GET /projects/meta
→ /projects/{project_id} 매칭 (project_id = "meta")
→ "meta"를 i32로 파싱 시도
→ 에러: "can not parse \"meta\" to a i32"
```

#### 3.2 해결 방법

```rust
// ✅ 올바른 순서
.route("/projects/meta", web::get().to(get_project_metadata::<P>))
.route("/projects/active", web::get().to(get_active_projects::<P>))
.route("/projects/{project_id}", web::get().to(get_project::<P>))
```

**원칙**:
1. **구체적 경로 먼저** (예: `/projects/meta`)
2. **동적 경로 나중** (예: `/projects/{project_id}`)

**이유**:
- Actix-web은 등록 순서대로 라우트 매칭
- 먼저 등록된 라우트가 우선순위 높음

## 🎨 프론트엔드 통합

### 1. API 점검 대시보드

#### 1.1 컴포넌트 구조

```
ApiHealthCheck
├── 통계 대시보드 (StatsBar)
│   ├── 전체
│   ├── 성공
│   ├── 실패
│   ├── 진행중
│   └── 대기
├── 일괄 테스트 버튼
└── 테스트 섹션 (TestSection)
    ├── 프로젝트 메타데이터 (3개)
    ├── 프로젝트 생명주기 (6개)
    └── 에러 처리 (2개)
```

#### 1.2 상태 관리

```typescript
interface TestResult {
  name: string;
  status: 'pending' | 'running' | 'success' | 'failure';
  duration?: number;
  request?: any;
  response?: any;
  error?: string;
}

interface TestSection {
  title: string;
  description: string;
  tests: TestResult[];
}
```

#### 1.3 테스트 실행 로직

```typescript
const runTest = async (sectionIndex: number, testIndex: number) => {
  // 1. 상태를 'running'으로 변경
  test.status = 'running';
  
  // 2. 시작 시간 기록
  const startTime = Date.now();
  
  try {
    // 3. API 호출
    const result = await runMetadataTest(testIndex);
    
    // 4. 성공 처리
    test.status = 'success';
    test.request = result.request;
    test.response = result.response;
    test.duration = Date.now() - startTime;
  } catch (error) {
    // 5. 실패 처리
    test.status = 'failure';
    test.error = error.message;
    test.duration = Date.now() - startTime;
  }
};
```

## 🔒 보안 고려사항

### 1. 인증/인가

**메타데이터 API**:
- 인증 불필요 (공개 정보)
- 누구나 접근 가능

**프로젝트 상태 변경 API**:
- 인증 필요
- 프로젝트 멤버만 변경 가능
- RBAC (Role-Based Access Control) 적용

### 2. 입력 검증

**상태 값 검증**:
```rust
// 잘못된 상태 값은 무시됨
// 에러를 반환하지 않고 200 응답
```

**개선 가능성**:
- 잘못된 상태 값 입력 시 400 Bad Request 반환
- 유효한 상태 목록을 에러 메시지에 포함

## 📈 성능 최적화

### 1. 컴파일 타임 최적화

```rust
pub const fn all() -> [ProjectStatus; 5] { ... }
pub const fn as_str(&self) -> &'static str { ... }
```

**효과**:
- 런타임 오버헤드 없음
- 정적 문자열 사용으로 힙 할당 없음

### 2. 메모리 효율성

```rust
&'static str  // 정적 문자열 참조
```

**효과**:
- 문자열 복사 없음
- 메모리 사용량 최소화

### 3. API 응답 크기

**메타데이터 응답 크기**: ~500 bytes (압축 전)

**최적화 가능성**:
- gzip 압축 적용 시 ~200 bytes
- HTTP/2 사용 시 헤더 압축

## 🔄 확장 가능성

### 1. 새로운 상태 추가

```rust
// 1. Enum에 variant 추가
pub enum ProjectStatus {
    Preparing,
    InProgress,
    Completed,
    OnHold,
    Cancelled,
    Archived,  // 새로운 상태
}

// 2. 메서드에 case 추가
pub const fn all() -> [ProjectStatus; 6] {  // 5 → 6
    [
        // ...
        ProjectStatus::Archived,
    ]
}

pub const fn as_str(&self) -> &'static str {
    match self {
        // ...
        ProjectStatus::Archived => "ARCHIVED",
    }
}

// 3. 컴파일러가 누락된 부분 자동 감지
```

### 2. 국제화 (i18n)

```rust
pub fn label(&self, locale: &str) -> &'static str {
    match (self, locale) {
        (ProjectStatus::Preparing, "ko") => "준비중",
        (ProjectStatus::Preparing, "en") => "Preparing",
        (ProjectStatus::Preparing, "ja") => "準備中",
        // ...
    }
}
```

### 3. 상태 전환 규칙

```rust
impl ProjectStatus {
    pub fn can_transition_to(&self, target: &ProjectStatus) -> bool {
        match (self, target) {
            (ProjectStatus::Preparing, ProjectStatus::InProgress) => true,
            (ProjectStatus::InProgress, ProjectStatus::OnHold) => true,
            (ProjectStatus::OnHold, ProjectStatus::InProgress) => true,
            (ProjectStatus::InProgress, ProjectStatus::Completed) => true,
            (_, ProjectStatus::Cancelled) => true,  // 언제든 취소 가능
            _ => false,
        }
    }
}
```
