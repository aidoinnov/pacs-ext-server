# 프로젝트 상태 메타데이터 API 및 E2E 테스트 작업 계획

## 📋 작업 개요

**목표**: 프로젝트 상태 관리 API의 안정성과 프론트엔드 개발 편의성 향상

**배경**:
- 프론트엔드가 프로젝트 상태 값을 하드코딩하여 사용 중
- 서버에서 상태 목록이 변경되면 프론트엔드 코드도 수정해야 함
- 프로젝트 상태 변경 기능에 대한 통합 테스트 부재
- API 동작을 수동으로 확인하기 어려움

**기대 효과**:
1. 프론트엔드가 서버에서 제공하는 정확한 상태 목록 사용
2. 상태 추가/변경 시 프론트엔드 코드 수정 불필요
3. 자동화된 테스트로 API 안정성 보장
4. 대시보드를 통한 실시간 API 점검 가능

---

## 🎯 작업 범위

### 1. 백엔드 개선

#### 1.1 ProjectStatus Enum 리팩토링
- **목표**: 상태 정보를 enum에 집중하여 단일 진실 공급원 확보
- **작업**:
  - `all()` 메서드 추가 - 모든 상태 반환
  - `as_str()` 메서드 추가 - DB 저장 값 반환
  - `label()` 메서드 추가 - 한글 라벨 반환
  - `description()` 메서드 추가 - 상태 설명 반환
  - `const fn`으로 구현하여 컴파일 타임 최적화
  - 불필요한 `#[sqlx(rename)]` 속성 제거 및 주석 추가

#### 1.2 메타데이터 API 구현
- **목표**: 프론트엔드에 사용 가능한 상태 목록 제공
- **작업**:
  - `ProjectStatusMeta` DTO 생성 (value, label, description)
  - `ProjectMetaResponse` DTO 생성 (available_statuses)
  - `get_project_metadata()` UseCase 메서드 추가
  - `GET /api/projects/meta` 엔드포인트 추가
  - 라우팅 순서 수정 (구체적 경로를 동적 경로보다 먼저 등록)

#### 1.3 통합 테스트 작성
- **목표**: 프로젝트 상태 변경 기능의 안정성 보장
- **작업**:
  - 프로젝트 상태 업데이트 통합 테스트 (9개)
  - 메타데이터 API 통합 테스트 (4개)
  - E2E 테스트 (3개)

### 2. 프론트엔드 개선

#### 2.1 API 점검 대시보드 추가
- **목표**: 개발자가 API 동작을 실시간으로 확인 가능
- **작업**:
  - `ApiHealthCheck` 컴포넌트 생성
  - 탭 네비게이션 추가 (인증 테스트 / API 점검)
  - 통계 대시보드 구현 (전체/성공/실패/진행중/대기)
  - 일괄 테스트 실행 기능
  - 개별 테스트 실행 기능
  - 요청/응답 상세 보기 기능

## ⚠️ 리스크 및 대응 방안

### 리스크 1: 라우팅 순서 문제
- **문제**: `/projects/meta`가 `/projects/{project_id}`와 충돌
- **증상**: "can not parse \"meta\" to a i32" 에러
- **대응**: 구체적 경로를 동적 경로보다 먼저 등록
- **상태**: ✅ 해결됨

### 리스크 2: 기존 API 호환성
- **문제**: 기존 프로젝트 API가 영향받을 수 있음
- **대응**: 기존 테스트 모두 통과 확인
- **상태**: ✅ 문제 없음

### 리스크 3: 프론트엔드 의존성
- **문제**: 대시보드가 서버에 의존
- **대응**: 서버 미실행 시 명확한 에러 메시지 표시
- **상태**: ✅ 처리됨
