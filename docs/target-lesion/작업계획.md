## 🎯 작업 목표

### 핵심 요구사항
1. **RECIST 병변(Lesion) 관리**
   - Target Lesion (측정 가능)
   - Non-target Lesion (측정 불가능)
   - New Lesion (Follow-up에서 새로 발견)

2. **Annotation과 Lesion 분리**
   - Annotation: 도형/마스크 데이터
   - Lesion: 의학적 해석 컨텍스트
   - TimePoint 이동 시 의미 보존

3. **Baseline 기준 추적**
   - Target/Non-target은 Baseline 연결 필수
   - New Lesion은 Baseline 연결 없음
   - Follow-up에서 Baseline 대비 변화 추적

## 📊 데이터 모델 설계

### 1. RECIST Lesion 테이블

#### `recist_lesion`
```sql
CREATE TABLE recist_lesion (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES security_project(id) ON DELETE CASCADE,
    subject_id INTEGER NOT NULL REFERENCES project_subject(id) ON DELETE CASCADE,
    lesion_type VARCHAR(20) NOT NULL CHECK (lesion_type IN ('TARGET', 'NON_TARGET', 'NEW')),
    lesion_number INTEGER NOT NULL,              -- Subject 내 병변 번호 (1, 2, 3, ...)
    baseline_timepoint_id INTEGER REFERENCES subject_timepoint(id) ON DELETE SET NULL,
    organ_site VARCHAR(100),                     -- 장기 위치 (Liver, Lung, ...)
    description TEXT,                            -- 병변 설명
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 제약 조건
    CONSTRAINT uq_subject_lesion_number UNIQUE (subject_id, lesion_number),
    
    -- TARGET/NON_TARGET은 baseline_timepoint_id 필수
    CONSTRAINT ck_baseline_required 
        CHECK (
            (lesion_type IN ('TARGET', 'NON_TARGET') AND baseline_timepoint_id IS NOT NULL)
            OR (lesion_type = 'NEW' AND baseline_timepoint_id IS NULL)
        )
);

CREATE INDEX idx_recist_lesion_subject ON recist_lesion(subject_id);
CREATE INDEX idx_recist_lesion_type ON recist_lesion(lesion_type);
CREATE INDEX idx_recist_lesion_baseline ON recist_lesion(baseline_timepoint_id);
```

#### `recist_lesion_annotation_map`
```sql
CREATE TABLE recist_lesion_annotation_map (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    lesion_id INTEGER NOT NULL REFERENCES recist_lesion(id) ON DELETE CASCADE,
    annotation_id INTEGER NOT NULL REFERENCES annotation_annotation(id) ON DELETE CASCADE,
    timepoint_id INTEGER NOT NULL REFERENCES subject_timepoint(id) ON DELETE CASCADE,
    measured_length_mm FLOAT,                    -- 측정된 길이 (mm)
    measured_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 제약 조건
    CONSTRAINT uq_lesion_annotation UNIQUE (lesion_id, annotation_id),
    CONSTRAINT uq_annotation_timepoint UNIQUE (annotation_id, timepoint_id)
);

CREATE INDEX idx_lesion_annotation_map_lesion ON recist_lesion_annotation_map(lesion_id);
CREATE INDEX idx_lesion_annotation_map_annotation ON recist_lesion_annotation_map(annotation_id);
CREATE INDEX idx_lesion_annotation_map_timepoint ON recist_lesion_annotation_map(timepoint_id);
```

### 2. Baseline 제약조건 추가

```sql
-- Subject당 Baseline 1개만 허용
CREATE UNIQUE INDEX ux_subject_baseline
ON subject_timepoint(subject_id)
WHERE visit_type = 'Baseline';
```

## 🔧 RECIST Lesion 규칙

### 1. Lesion Type별 규칙

| lesion_type | baseline_timepoint_id | 생성 가능 TimePoint | 측정 |
|-------------|----------------------|-------------------|------|
| TARGET      | 필수 (NOT NULL)       | Baseline만         | 필수 |
| NON_TARGET  | 필수 (NOT NULL)       | Baseline만         | 선택 |
| NEW         | NULL                 | Follow-up만        | 선택 |

### 2. 생성 제약

- **Baseline TimePoint**
  - `lesion_type = 'TARGET'` 생성 가능
  - `lesion_type = 'NON_TARGET'` 생성 가능
  - `lesion_type = 'NEW'` 생성 **금지** (서버 검증)

- **Follow-up TimePoint**
  - `lesion_type = 'NEW'` 생성 가능
  - 기존 Lesion에 대한 Annotation 추가 가능

### 3. Annotation 연결 규칙

- 하나의 Annotation은 하나의 Lesion에만 연결
- 하나의 Lesion은 여러 TimePoint에서 여러 Annotation 가질 수 있음
- TimePoint는 사용자 입력이 아니라 **컨텍스트에서 자동 상속**

## 📡 API 설계

### 1. RECIST Lesion API

#### (1) Lesion 생성
```
POST /api/subjects/{subject_id}/lesions
```

**Request**:
```json
{
  "lesion_type": "TARGET",
  "baseline_timepoint_id": 1,
  "organ_site": "Liver",
  "description": "Right lobe lesion"
}
```

**Response** (201):
```json
{
  "id": 1,
  "project_id": 1,
  "subject_id": 1,
  "lesion_type": "TARGET",
  "lesion_number": 1,
  "baseline_timepoint_id": 1,
  "organ_site": "Liver",
  "description": "Right lobe lesion",
  "created_at": "2026-01-18T10:00:00Z",
  "updated_at": "2026-01-18T10:00:00Z"
}
```

#### (2) Lesion 목록 조회
```
GET /api/subjects/{subject_id}/lesions
```

**Query Parameters**:
- `lesion_type` (optional): TARGET | NON_TARGET | NEW
- `baseline_timepoint_id` (optional): Baseline TimePoint ID

**Response** (200):
```json
{
  "lesions": [
    {
      "id": 1,
      "lesion_type": "TARGET",
      "lesion_number": 1,
      "baseline_timepoint_id": 1,
      "organ_site": "Liver",
      "annotation_count": 3
    }
  ]
}
```

#### (3) Lesion 상세 조회
```
GET /api/lesions/{id}
```

**Response** (200):
```json
{
  "id": 1,
  "lesion_type": "TARGET",
  "lesion_number": 1,
  "baseline_timepoint_id": 1,
  "organ_site": "Liver",
  "description": "Right lobe lesion",
  "annotations": [
    {
      "timepoint_id": 1,
      "timepoint_name": "BL",
      "annotation_id": 123,
      "measured_length_mm": 25.5,
      "measured_at": "2026-01-18T10:00:00Z"
    },
    {
      "timepoint_id": 2,
      "timepoint_name": "TP1",
      "annotation_id": 456,
      "measured_length_mm": 20.3,
      "measured_at": "2026-02-18T10:00:00Z"
    }
  ]
}
```

#### (4) Lesion 수정
```
PUT /api/lesions/{id}
```

**Request**:
```json
{
  "organ_site": "Liver (Right lobe)",
  "description": "Updated description"
}
```

#### (5) Lesion 삭제
```
DELETE /api/lesions/{id}
```

### 2. Annotation API 확장

#### Annotation 생성 시 RECIST 정보 포함
```
POST /api/annotations
```

**Request**:
```json
{
  "project_id": 1,
  "study_uid": "1.2.840...",
  "series_uid": "1.2.840...",
  "instance_uid": "1.2.840...",
  "data": {
    "type": "line",
    "points": [[100, 100], [150, 150]]
  },
  "recist": {
    "lesion_id": 1,
    "measured_length_mm": 25.5
  }
}
```

**서버 동작**:
1. Annotation 생성
2. Study → TimePoint 조회 (컨텍스트 자동 상속)
3. `recist_lesion_annotation_map` 생성
4. `measured_length_mm` 저장

**Response** (201):
```json
{
  "id": 123,
  "project_id": 1,
  "study_uid": "1.2.840...",
  "data": { ... },
  "recist": {
    "lesion_id": 1,
    "timepoint_id": 1,
    "measured_length_mm": 25.5
  }
}
```

### 3. New Lesion 생성 API

```
POST /api/annotations
```

**Request** (New Lesion):
```json
{
  "project_id": 1,
  "study_uid": "1.2.840...",
  "series_uid": "1.2.840...",
  "instance_uid": "1.2.840...",
  "data": {
    "type": "line",
    "points": [[100, 100], [150, 150]]
  },
  "recist": {
    "create_new_lesion": true,
    "organ_site": "Lung",
    "description": "New lesion in right lung"
  }
}
```

**서버 동작**:
1. Annotation 생성
2. Study → TimePoint 조회
3. **TimePoint가 Baseline인지 검증** (Baseline이면 에러)
4. `recist_lesion` 생성 (lesion_type='NEW', baseline_timepoint_id=NULL)
5. `recist_lesion_annotation_map` 생성

## 🚨 주의사항

### 1. Baseline 검증
- New Lesion은 Baseline TimePoint에서 생성 금지
- 서버에서 반드시 검증 필요

### 2. TimePoint 컨텍스트
- Annotation 생성 시 Study → TimePoint 자동 조회
- 사용자가 TimePoint를 직접 선택하지 않음
- Study가 TimePoint에 할당되지 않은 경우 에러

### 3. Lesion Number 자동 생성
- Subject 내에서 순차적으로 증가 (1, 2, 3, ...)
- 동시성 이슈 대비 필요

### 4. 트랜잭션 안전성
- Annotation + Lesion Map 생성은 트랜잭션으로 묶기
- 실패 시 롤백 보장
