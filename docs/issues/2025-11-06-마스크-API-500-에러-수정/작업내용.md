## 🔍 원인 분석

### 1차 원인: MaskUseCase가 app_data에 등록되지 않음

Actix-web의 `Data<T>` extractor는 `App::app_data()`에 등록된 타입만 추출할 수 있습니다. 
`MaskUseCase`가 등록되지 않아서 핸들러에서 추출 실패.

### 2차 원인: Rust 소유권 문제

```rust
// ❌ 문제 코드 (main.rs:351-355)
let mask_use_case = Arc::new(MaskUseCase::new(
    mask_service,  // ← mask_service가 여기서 move됨!
    mask_group_service.clone(),
    signed_url_service.clone(),
));
```

`mask_service`가 `MaskUseCase::new()`로 move되어 소비되었기 때문에, 
이후에 다른 곳에서 사용하려고 하면 컴파일 에러 발생.

## ✅ 해결 방법

### 1. mask_service를 clone하여 사용

**파일**: `pacs-server/src/main.rs`  
**라인**: 351-355

#### 변경 전
```rust
let mask_use_case = Arc::new(MaskUseCase::new(
    mask_service,  // ❌ move
    mask_group_service.clone(),
    signed_url_service.clone(),
));
```

#### 변경 후
```rust
let mask_use_case = Arc::new(MaskUseCase::new(
    mask_service.clone(),  // ✅ clone
    mask_group_service.clone(),
    signed_url_service.clone(),
));
```

### 2. MaskUseCase 및 관련 서비스를 app_data에 등록

**파일**: `pacs-server/src/main.rs`  
**라인**: 510-513

#### 추가된 코드
```rust
// Mask services and use cases for mask controller
.app_data(web::Data::new(mask_use_case.clone()))
.app_data(web::Data::new(mask_group_use_case.clone()))
.app_data(web::Data::new(signed_url_service.clone()))
```

### 3. 디버그 로깅 활성화

**파일**: `pacs-server/src/main.rs`  
**라인**: 405-406


## 📝 배운 점

### Actix-web Data Extractor
- `Data<T>`는 `App::app_data(web::Data::new(value))`로 등록된 타입만 추출 가능
- 제네릭 타입의 경우 정확히 일치해야 함 (타입 시그니처 중요!)

### Rust 소유권
- `Arc::clone()`은 참조 카운트만 증가 (얕은 복사)
- Move semantics를 이해하고 적절히 clone 사용
- 컴파일러 경고 메시지를 주의 깊게 읽기 (`unused variable`)

### 디버깅 팁
- Actix-web의 디버그 로그를 활성화하면 Data extractor 실패 원인 파악 가능
- 에러 메시지에 전체 타입 시그니처가 나오므로 정확히 매칭 필요
