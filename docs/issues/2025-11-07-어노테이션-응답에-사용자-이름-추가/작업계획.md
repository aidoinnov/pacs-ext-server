# 작업계획: Annotation 응답에 사용자 이름 추가

## 📋 이슈 개요

### 배경
- 현재 Annotation API 응답에는 `user_id`만 포함되어 있음
- 프론트엔드에서 작성자 이름을 표시하려면 추가 API 호출이 필요
- 사용자 경험 개선을 위해 응답에 작성자 이름을 포함해야 함

### 목표
- Annotation 응답 DTO에 `user_name` 필드 추가
- 모든 annotation 조회 API에서 작성자 이름 반환
- **N+1 쿼리 문제 방지**: 배치 쿼리로 성능 최적화

### 제약사항
- 기존 API 호환성 유지 (`user_id` 필드는 그대로 유지)
- 성능 저하 방지: 목록 조회 시 사용자 정보를 한 번에 조회
- 사용자 정보가 없는 경우 graceful handling (Option<String>)

## 🎯 작업 범위

### 1. Domain Layer
- **UserRepository 트레이트**
  - `find_by_ids(&[i32])` 메서드 추가
  - 여러 사용자 ID를 한 번에 조회하는 배치 메서드

### 2. Infrastructure Layer
- **UserRepositoryImpl**
  - PostgreSQL `ANY($1)` 연산자를 사용한 배치 조회 구현
  - 빈 배열 처리 (early return)

### 3. Application Layer
- **AnnotationResponse DTO**
  - `user_name: Option<String>` 필드 추가
  - OpenAPI 스키마 업데이트

- **AnnotationUseCase**
  - UserRepository 의존성 추가
  - 헬퍼 메서드 구현:
    - `to_response()`: 단일 조회용
    - `to_responses()`: 배치 최적화 목록 변환
  - 모든 조회 메서드에 헬퍼 적용

### 4. Presentation Layer
- **annotation_controller.rs**
  - AnnotationUseCase 제네릭 타입 시그니처 업데이트
  - 모든 핸들러 함수의 타입 파라미터 수정

### 5. Main Application
- **main.rs**
  - AnnotationUseCase 생성 시 UserRepository 주입

## 📊 성능 최적화 전략

### 문제: N+1 쿼리
```
GET /api/annotations?study_instance_uid=xxx
→ 100개의 annotation 조회
→ 각 annotation마다 user 조회 (100번)
→ 총 101번의 DB 쿼리 ❌
```

### 해결: 배치 쿼리
```
GET /api/annotations?study_instance_uid=xxx
→ 100개의 annotation 조회 (1번)
→ 고유한 user_id 수집 (예: 10명)
→ 10명의 user를 한 번에 조회 (1번)
→ HashMap으로 O(1) 매핑
→ 총 2번의 DB 쿼리 ✅
```

### 구현 방법
1. **고유 user_id 수집**: HashSet으로 중복 제거
2. **배치 조회**: `WHERE id = ANY($1)` 쿼리
3. **HashMap 생성**: user_id → full_name 매핑
4. **O(1) 조회**: HashMap.get()으로 빠른 매핑

## 🚀 예상 결과

### API 응답 변화

**Before:**
```json
{
  "id": 123,
  "user_id": 5,
  "study_instance_uid": "1.2.3.4.5",
  "annotation_data": {...}
}
```

**After:**
```json
{
  "id": 123,
  "user_id": 5,
  "user_name": "홍길동",
  "study_instance_uid": "1.2.3.4.5",
  "annotation_data": {...}
}
```

### 성능 개선
- **쿼리 횟수**: N+1 → 2
- **응답 시간**: 유사 또는 개선
- **메모리 사용**: 미미한 증가 (HashMap)

## ⚠️ 주의사항

1. **Null 처리**: full_name이 null인 경우 user_name도 null
2. **삭제된 사용자**: user가 삭제된 경우 user_name은 null
3. **Arc::clone()**: 참조 카운트만 증가, 실제 데이터 복사 아님
4. **제네릭 타입**: 모든 타입 시그니처에 UserRepository 추가 필요
