## 🔐 AWS S3 Presigned URL

### 개념

**Presigned URL**은 AWS 자격 증명 없이도 S3 객체에 대한 임시 액세스를 제공하는 URL입니다.

#### 주요 특징
- **시간 제한**: URL은 지정된 시간(TTL) 동안만 유효
- **서명 기반**: AWS Signature Version 4를 사용하여 서명
- **권한 위임**: 서버의 AWS 자격 증명을 사용하여 클라이언트에게 임시 권한 부여
- **보안**: 서명된 헤더만 요청에 포함 가능

### Presigned URL 생성 과정

```rust
use aws_sdk_s3::presigning::PresigningConfig;
use std::time::Duration;

// 1. Presigning 설정 생성
let presigning_config = PresigningConfig::expires_in(
    Duration::from_secs(600)  // 10분 유효
)?;

// 2. PutObject 요청 빌더 생성
let mut put_object = client
    .put_object()
    .bucket("my-bucket")
    .key("path/to/file.png");

// 3. Content-Type 설정 (서명에 포함됨)
put_object = put_object.content_type("image/png");

// 4. Presigned URL 생성
let presigned_request = put_object
    .presigned(presigning_config)
    .await?;

// 5. URL 추출
let url = presigned_request.uri().to_string();
```

### 서명 메커니즘

#### AWS Signature Version 4

Presigned URL은 다음 정보를 포함하여 서명됩니다:

1. **HTTP 메서드**: `PUT`, `GET` 등
2. **리소스 경로**: S3 버킷과 객체 키
3. **쿼리 파라미터**: `X-Amz-Algorithm`, `X-Amz-Credential` 등
4. **서명된 헤더**: `X-Amz-SignedHeaders`에 명시된 헤더들
5. **만료 시간**: `X-Amz-Expires`

#### 서명된 헤더 (X-Amz-SignedHeaders)

**중요**: 클라이언트가 전송하는 모든 헤더는 **반드시** `X-Amz-SignedHeaders`에 포함되어야 합니다.

**예시**:
```
X-Amz-SignedHeaders=content-type;host
```

이 경우 클라이언트는 **오직** `Content-Type`과 `Host` 헤더만 전송해야 합니다.

### 403 에러 발생 원인

#### 시나리오 1: 서명되지 않은 헤더 전송

**서버가 생성한 Presigned URL**:
```
https://bucket.s3.region.amazonaws.com/key?
  X-Amz-SignedHeaders=content-type;host&
  X-Amz-Signature=...
```

**클라이언트가 전송한 요청**:
```http
PUT /key HTTP/1.1
Host: bucket.s3.region.amazonaws.com
Content-Type: image/png
x-amz-acl: private                    ❌ 서명되지 않음!
x-amz-storage-class: STANDARD         ❌ 서명되지 않음!
x-amz-meta-user_id: 123               ❌ 서명되지 않음!
```

**결과**: 403 AccessDenied
```xml
<Error>
  <Code>AccessDenied</Code>
  <Message>There were headers present in the request which were not signed</Message>
  <HeadersNotSigned>x-amz-acl, x-amz-storage-class, x-amz-meta-user_id</HeadersNotSigned>
</Error>
```

#### 해결 방법

**방법 1: 서버에서 헤더를 서명에 포함** (복잡)
```rust
let put_object = client
    .put_object()
    .bucket("bucket")
    .key("key")
    .content_type("image/png")
    .acl(ObjectCannedAcl::Private)              // 서명에 포함
    .storage_class(StorageClass::Standard)      // 서명에 포함
    .metadata("user_id", "123");                // 서명에 포함
```

**방법 2: 불필요한 헤더 제거** (단순) ✅ **채택**
```rust
let put_object = client
    .put_object()
    .bucket("bucket")
    .key("key")
    .content_type("image/png");  // Content-Type만!
```

### 메타데이터 vs 헤더

#### S3 메타데이터
- **저장 위치**: S3 객체의 메타데이터로 저장
- **접두사**: `x-amz-meta-*`
- **용도**: 객체에 대한 추가 정보 저장
- **제약**: Presigned URL 사용 시 서명 필요

#### 대안: 데이터베이스에 메타데이터 저장
```rust
// ✅ 권장: 메타데이터를 DB에 저장
struct Mask {
    id: i32,
    file_path: String,
    annotation_id: i32,
    mask_group_id: i32,
    user_id: i32,
    // ... 기타 메타데이터
}

// S3에는 파일만 저장
// Presigned URL은 Content-Type만 포함
```

## 🌐 Actix-web 라우팅

### 라우트 스코프 (Scope)

#### 개념

**Scope**는 라우트를 그룹화하고 공통 경로 접두사를 공유하는 메커니즘입니다.

#### 기본 사용법

```rust
use actix_web::{web, App, HttpServer};

HttpServer::new(|| {
    App::new()
        .service(
            web::scope("/api")
                .route("/users", web::get().to(get_users))
                .route("/users/{id}", web::get().to(get_user))
        )
})
```

**결과 경로**:
- `GET /api/users`
- `GET /api/users/{id}`

### 중첩 스코프 (Nested Scopes)

#### 계층 구조

```rust
App::new()
    .service(
        web::scope("/api")                          // Level 1
            .service(
                web::scope("/annotations")          // Level 2
                    .route("", web::get().to(list_annotations))
                    .route("/{id}", web::get().to(get_annotation))
                    .service(
                        web::scope("/{annotation_id}/mask-groups")  // Level 3
                            .route("", web::get().to(list_mask_groups))
                            .route("/{group_id}", web::get().to(get_mask_group))
                            .service(
                                web::scope("/{group_id}/masks")      // Level 4
                                    .route("", web::get().to(list_masks))
                                    .route("/{mask_id}", web::get().to(get_mask))
                            )
                    )
            )
    )
```

**결과 경로**:
- `GET /api/annotations`
- `GET /api/annotations/{id}`
- `GET /api/annotations/{annotation_id}/mask-groups`
- `GET /api/annotations/{annotation_id}/mask-groups/{group_id}`
- `GET /api/annotations/{annotation_id}/mask-groups/{group_id}/masks`
- `GET /api/annotations/{annotation_id}/mask-groups/{group_id}/masks/{mask_id}`

### 라우트 등록 방식

#### 방식 1: 직접 등록

```rust
web::scope("/api/annotations")
    .route("/{annotation_id}/masks", web::get().to(list_masks))
    .route("/{annotation_id}/masks/{mask_id}", web::get().to(get_mask))
```

#### 방식 2: configure 함수 사용

```rust
// controller.rs
pub fn configure_routes(cfg: &mut web::ServiceConfig) {
    cfg.service(
        web::scope("/api/annotations")
            .route("/{annotation_id}/masks", web::get().to(list_masks))
            .route("/{annotation_id}/masks/{mask_id}", web::get().to(get_mask))
    );
}

// main.rs
App::new()
    .configure(configure_routes)
```

### 404 에러 발생 원인

#### 시나리오: 라우트 미등록

**의도한 경로**:
```
POST /api/annotations/{annotation_id}/mask-groups/{group_id}/masks
```

**실제 등록된 라우트**:
```rust
// main.rs
App::new()
    .configure(annotation_controller::configure_routes)  // ✅ 등록됨
    .configure(mask_controller::configure_routes)        // ❌ 잘못된 스코프
```

**mask_controller.rs**:
```rust
pub fn configure_routes(cfg: &mut web::ServiceConfig) {
    cfg.service(
        web::scope("/masks")  // ❌ 잘못된 경로: /masks
            .route("", web::post().to(create_mask))
    );
}
```

**결과**: 
- 등록된 경로: `POST /masks`
- 요청한 경로: `POST /api/annotations/{annotation_id}/mask-groups/{group_id}/masks`
- **404 Not Found**

#### 해결 방법

**annotation_controller.rs에 통합**:
```rust
pub fn configure_routes(cfg: &mut web::ServiceConfig) {
    cfg.service(
        web::scope("/api/annotations")
            .route("/{annotation_id}/mask-groups/{group_id}/masks", 
                   web::post().to(mask_controller::create_mask))
    );
}
```

**결과**:
- 등록된 경로: `POST /api/annotations/{annotation_id}/mask-groups/{group_id}/masks` ✅
- 요청한 경로: `POST /api/annotations/{annotation_id}/mask-groups/{group_id}/masks` ✅
- **200 OK**

## 🔧 Rust AWS SDK

### aws-sdk-s3 크레이트

#### 주요 타입

```rust
use aws_sdk_s3::{
    Client,                          // S3 클라이언트
    config::Region,                  // AWS 리전
    presigning::PresigningConfig,    // Presigned URL 설정
    types::{
        ObjectCannedAcl,             // ACL 설정
        StorageClass,                // Storage Class
    },
};
```

#### 클라이언트 초기화

```rust
use aws_config::meta::region::RegionProviderChain;
use aws_sdk_s3::Client;

// 리전 설정
let region_provider = RegionProviderChain::default_provider()
    .or_else("ap-northeast-2");

// AWS 설정 로드
let config = aws_config::from_env()
    .region(region_provider)
    .load()
    .await;

// S3 클라이언트 생성
let client = Client::new(&config);
```

#### PutObject 요청

```rust
// 기본 사용
let response = client
    .put_object()
    .bucket("my-bucket")
    .key("path/to/file.png")
    .body(file_bytes.into())
    .send()
    .await?;

// Presigned URL 생성
let presigned = client
    .put_object()
    .bucket("my-bucket")
    .key("path/to/file.png")
    .content_type("image/png")
    .presigned(PresigningConfig::expires_in(Duration::from_secs(600))?)
    .await?;

let url = presigned.uri().to_string();
```

### 에러 처리

```rust
use aws_sdk_s3::error::SdkError;
use aws_sdk_s3::operation::put_object::PutObjectError;

match client.put_object().send().await {
    Ok(response) => {
        // 성공
    }
    Err(SdkError::ServiceError(err)) => {
        match err.err() {
            PutObjectError::NoSuchBucket(_) => {
                // 버킷이 존재하지 않음
            }
            _ => {
                // 기타 S3 에러
            }
        }
    }
    Err(e) => {
        // SDK 에러 (네트워크, 설정 등)
    }
}
```

## 📊 성능 고려사항

### Presigned URL TTL 설정

```rust
// ❌ 너무 짧음: 업로드 실패 가능
PresigningConfig::expires_in(Duration::from_secs(60))  // 1분

// ✅ 적절함: 대부분의 업로드 완료 가능
PresigningConfig::expires_in(Duration::from_secs(600))  // 10분

// ⚠️ 너무 김: 보안 위험
PresigningConfig::expires_in(Duration::from_secs(86400))  // 24시간
```

### 라우트 등록 순서

```rust
// ❌ 잘못된 순서: 구체적인 경로가 먼저
web::scope("/api")
    .route("/users/{id}", web::get().to(get_user))
    .route("/users/me", web::get().to(get_current_user))  // 절대 매칭 안됨!

// ✅ 올바른 순서: 구체적인 경로가 먼저
web::scope("/api")
    .route("/users/me", web::get().to(get_current_user))
    .route("/users/{id}", web::get().to(get_user))
```

## 🔒 보안 고려사항

### Presigned URL 보안

1. **TTL 최소화**: 필요한 만큼만 유효 시간 설정
2. **HTTPS 사용**: 항상 HTTPS로 URL 생성
3. **로깅**: Presigned URL 생성 및 사용 로그 기록
4. **권한 검증**: URL 생성 전 사용자 권한 확인

### S3 버킷 정책

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "StringEquals": {
          "s3:x-amz-server-side-encryption": "AES256"
        }
      }
    }
  ]
}
```
