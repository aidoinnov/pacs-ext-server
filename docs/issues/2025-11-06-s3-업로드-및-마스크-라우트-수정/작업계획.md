## 📋 이슈 개요

**날짜**: 2025-11-06  
**브랜치**: `fix/mask-upload-and-route-issues`  
**담당자**: AI Assistant  
**우선순위**: 높음

### 문제 요약

1. **S3 Presigned URL 업로드 403 에러**
   - 클라이언트가 S3에 파일 업로드 시 403 Forbidden 에러 발생
   - 에러 메시지: "There were headers present in the request which were not signed"

2. **Mask API 404 에러**
   - `POST /api/annotations/{annotation_id}/mask-groups/{group_id}/masks` 엔드포인트 404 에러
   - 라우트 스코프 설정 문제로 인한 엔드포인트 미등록

## 🎯 작업 목표

### 1단계: 문제 원인 분석
- [x] S3 403 에러 원인 파악
  - AWS S3 presigned URL 서명 메커니즘 이해
  - 클라이언트가 전송하는 헤더 분석
  - 서버가 생성하는 presigned URL 서명 분석
  
- [x] Mask API 404 에러 원인 파악
  - Actix-web 라우트 설정 검토
  - 라우트 스코프 계층 구조 분석
  - 엔드포인트 등록 상태 확인

### 2단계: 해결 방안 설계

#### S3 업로드 문제 해결 방안
**선택된 방안**: Presigned URL 단순화
- 서버: Content-Type만 포함한 presigned URL 생성
- 클라이언트: Content-Type만 전송
- 불필요한 헤더 제거: ACL, Storage Class, 메타데이터

**대안 (미채택)**:
- 모든 헤더를 presigned URL 서명에 포함 (복잡도 증가)
- 클라이언트 측에서만 수정 (서버 측 제어 불가)

#### Mask API 라우트 문제 해결 방안
**선택된 방안**: 라우트 병합
- Mask 라우트를 `annotation_controller.rs`에 통합
- `main.rs`에서 중복 등록 제거
- 일관된 라우트 계층 구조 유지
