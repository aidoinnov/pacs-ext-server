## 개요

### 목적
Keycloak을 활용한 안전하고 확장 가능한 인증 시스템 구축

### 주요 기술 스택
- **인증 서버**: Keycloak (OpenID Connect)
- **백엔드**: Rust (Actix-web)
- **HTTP 클라이언트**: reqwest
- **아키텍처 패턴**: Clean Architecture

### 핵심 개선사항
1. Service account 기반 관리 작업
2. 토큰 갱신 메커니즘
3. 관리자 승인 기반 회원가입
4. 인증 프록시 구조

## 주요 컴포넌트

### 1. KeycloakClient

**위치**: `pacs-server/src/infrastructure/external/keycloak_client.rs`

**책임**:
- Keycloak API와의 직접 통신
- HTTP 요청/응답 처리
- 토큰 관리

**주요 필드**:
```rust
pub struct KeycloakClient {
    base_url: String,           // Keycloak 서버 URL
    realm: String,              // Realm 이름
    client_id: String,          // Client ID
    client_secret: String,      // Client Secret
    admin_username: String,     // (Deprecated) Admin 사용자명
    admin_password: String,     // (Deprecated) Admin 비밀번호
    http_client: Client,        // HTTP 클라이언트
}
```

**주요 메서드**:

| 메서드 | 설명 | 권한 |
|--------|------|------|
| `get_admin_token()` | Admin 토큰 획득 | Service Account |
| `create_user()` | 사용자 생성 | Admin |
| `delete_user()` | 사용자 삭제 (ID) | Admin |
| `delete_user_by_username()` | 사용자 삭제 (Username) | Admin |
| `update_user_enabled()` | 사용자 활성화/비활성화 | Admin |
| `reset_user_password()` | 비밀번호 재설정 | Admin |
| `authenticate_user()` | 사용자 인증 | Public |
| `refresh_access_token()` | 토큰 갱신 | Public |
| `assign_realm_role_to_user()` | 역할 할당 | Admin |
| `add_user_to_group()` | 그룹 추가 | Admin |

## 인증 플로우

### 1. 회원가입 플로우

```
Client                  API Server              Keycloak
  │                         │                       │
  ├─ POST /api/auth/register                       │
  │  {username, email, pw}  │                       │
  │                         │                       │
  │                         ├─ get_admin_token() ──→│
  │                         │                       │
  │                         │←─ admin_access_token ─┤
  │                         │                       │
  │                         ├─ create_user() ──────→│
  │                         │  enabled: false       │
  │                         │  emailVerified: true  │
  │                         │                       │
  │                         │←─ user_id ────────────┤
  │                         │                       │
  │                         ├─ assign_role() ──────→│
  │                         │  role: "user"         │
  │                         │                       │
  │←─ 201 Created ──────────┤                       │
  │  "관리자 승인 대기"      │                       │
```

**주요 특징**:
- 사용자는 비활성화 상태로 생성 (`enabled: false`)
- 이메일은 인증된 것으로 간주 (`emailVerified: true`)
- 추가 액션 불필요 (`requiredActions: []`)
- 기본 "user" 역할 자동 할당

---

### 2. 로그인 플로우

```
Client                  API Server              Keycloak
  │                         │                       │
  ├─ POST /api/auth/login   │                       │
  │  {username, password}   │                       │
  │                         │                       │
  │                         ├─ authenticate_user()─→│
  │                         │  grant_type: password │
  │                         │                       │
  │                         │←─ tokens ─────────────┤
  │                         │  access_token         │
  │                         │  refresh_token        │
  │                         │  expires_in           │
  │                         │                       │
  │←─ 200 OK ───────────────┤                       │
  │  {access_token,         │                       │
  │   refresh_token, ...}   │                       │
```

**주요 특징**:
- Username/password 기반 인증
- Keycloak과 직접 통신하지 않음 (프록시 구조)
- Access token과 refresh token 동시 반환
- Client credentials 포함하여 보안 강화

---

### 3. 토큰 갱신 플로우

```
Client                  API Server              Keycloak
  │                         │                       │
  ├─ POST /api/auth/refresh │                       │
  │  {refresh_token}        │                       │
  │                         │                       │
  │                         ├─ refresh_access_token()→│
  │                         │  grant_type: refresh_token│
  │                         │  client_secret        │
  │                         │                       │
  │                         │←─ new_tokens ─────────┤
  │                         │  new_access_token     │
  │                         │  new_refresh_token    │
  │                         │                       │
  │←─ 200 OK ───────────────┤                       │
  │  {new_access_token,     │                       │
  │   new_refresh_token}    │                       │
```

**주요 특징**:
- Refresh token으로 새로운 access token 발급
- 새로운 refresh token도 함께 발급 (토큰 로테이션)
- Client secret 포함하여 보안 강화
- 재로그인 없이 세션 유지

---

### 4. 관리자 승인 플로우

```
Admin                   API Server              Keycloak
  │                         │                       │
  ├─ PUT /api/users/{id}/approve                   │
  │                         │                       │
  │                         ├─ get_admin_token() ──→│
  │                         │                       │
  │                         │←─ admin_token ────────┤
  │                         │                       │
  │                         ├─ update_user_enabled()→│
  │                         │  enabled: true        │
  │                         │                       │
  │                         │←─ success ────────────┤
  │                         │                       │
  │←─ 200 OK ───────────────┤                       │
```

**주요 특징**:
- 관리자가 수동으로 사용자 승인
- `enabled: true`로 변경하여 로그인 허용
- Service account 토큰으로 작업 수행

## 보안 고려사항

### 1. Service Account 사용

**이전 방식 (Password Grant)**:
```rust
// ❌ 보안 위험: Admin 계정 정보 노출
let params = [
    ("grant_type", "password"),
    ("username", &self.admin_username),  // 평문 저장
    ("password", &self.admin_password),  // 평문 저장
    ("client_id", &self.client_id),
];
```

**개선된 방식 (Client Credentials)**:
```rust
// ✅ 안전: Service account 사용
let params = [
    ("grant_type", "client_credentials"),
    ("client_id", &self.client_id),
    ("client_secret", &self.client_secret),  // 환경 변수로 관리
];
```

**장점**:
- Admin 사용자 계정 정보 노출 위험 제거
- Client secret만 안전하게 관리하면 됨
- Keycloak 권장 방식
- 감사 로그에서 작업 주체 명확히 구분

---

### 2. 토큰 보안

#### Access Token
- **유효 기간**: 5분 (300초)
- **저장 위치**: 메모리 (localStorage 사용 금지)
- **전송 방식**: Authorization Bearer 헤더

#### Refresh Token
- **유효 기간**: 30분 (1800초)
- **저장 위치**: HttpOnly Cookie (권장) 또는 Secure Storage
- **전송 방식**: POST body (HTTPS 필수)
- **로테이션**: 갱신 시 새로운 refresh token 발급

#### 보안 권장사항
```javascript
// ✅ 권장: Access token은 메모리에만 저장
let accessToken = null;

// ❌ 금지: localStorage에 저장
// localStorage.setItem('access_token', token);  // XSS 공격 위험

// ✅ 권장: Refresh token은 HttpOnly Cookie
// Set-Cookie: refresh_token=...; HttpOnly; Secure; SameSite=Strict

// ✅ 권장: HTTPS 사용 필수
if (window.location.protocol !== 'https:') {
  console.error('HTTPS required for secure token handling');
}
```

### 2. 토큰 캐싱 (향후 개선)

**현재 구조**:
```rust
// 매번 새로운 admin token 요청
async fn get_admin_token(&self) -> Result<String, ServiceError> {
    // Keycloak에 요청
}
```

**개선 방안**:
```rust
// 토큰 캐싱 (TTL 고려)
pub struct KeycloakClient {
    admin_token_cache: Arc<RwLock<Option<CachedToken>>>,
}

struct CachedToken {
    token: String,
    expires_at: Instant,
}

async fn get_admin_token(&self) -> Result<String, ServiceError> {
    // 1. 캐시 확인
    if let Some(cached) = self.admin_token_cache.read().await.as_ref() {
        if cached.expires_at > Instant::now() {
            return Ok(cached.token.clone());
        }
    }

    // 2. 새로운 토큰 요청
    let token = self.request_new_admin_token().await?;

    // 3. 캐시 업데이트
    *self.admin_token_cache.write().await = Some(CachedToken {
        token: token.clone(),
        expires_at: Instant::now() + Duration::from_secs(270), // 5분 - 30초 버퍼
    });

    Ok(token)
}
```

**예상 효과**:
- Keycloak 요청 횟수 감소
- 응답 시간 단축
- Keycloak 서버 부하 감소

```rust
async fn test_concurrent_authentication() {
    let client = Arc::new(KeycloakClient::new(/* ... */));
    let mut handles = vec![];

    for i in 0..100 {
        let client = client.clone();
        let handle = tokio::spawn(async move {
            client.authenticate_user(&format!("user{}", i), "pass").await
        });
        handles.push(handle);
    }

    let results = futures::future::join_all(handles).await;
    let success_count = results.iter().filter(|r| r.is_ok()).count();

    assert!(success_count >= 95); // 95% 이상 성공
}
```

## 모니터링 및 관찰성

### 1. 메트릭 수집

```rust
// Prometheus 메트릭 예시
use prometheus::{Counter, Histogram};

lazy_static! {
    static ref AUTH_REQUESTS: Counter = Counter::new(
        "keycloak_auth_requests_total",
        "Total number of authentication requests"
    ).unwrap();

    static ref AUTH_DURATION: Histogram = Histogram::new(
        "keycloak_auth_duration_seconds",
        "Authentication request duration"
    ).unwrap();
}

pub async fn authenticate_user(&self, username: &str, password: &str)
    -> Result<KeycloakTokenResponse, ServiceError>
{
    AUTH_REQUESTS.inc();
    let timer = AUTH_DURATION.start_timer();

    let result = self.do_authenticate(username, password).await;

    timer.observe_duration();
    result
}
```

### 2. 분산 추적

```rust
use tracing::{info, warn, error, instrument};

#[instrument(skip(self, password))]
pub async fn authenticate_user(
    &self,
    username: &str,
    password: &str,
) -> Result<KeycloakTokenResponse, ServiceError> {
    info!("Authenticating user: {}", username);

    let result = self.do_authenticate(username, password).await;

    match &result {
        Ok(_) => info!("Authentication successful for user: {}", username),
        Err(e) => warn!("Authentication failed for user {}: {}", username, e),
    }

    result
}
```

### 1. 환경 변수

```bash
# .env.production
KEYCLOAK_URL=https://keycloak.production.com
KEYCLOAK_REALM=production-realm
KEYCLOAK_CLIENT_ID=pacs-server
KEYCLOAK_CLIENT_SECRET=<secret>

# Deprecated (하위 호환성)
KEYCLOAK_ADMIN_USERNAME=admin
KEYCLOAK_ADMIN_PASSWORD=<password>
```

### 2. Keycloak 설정

#### Service Account 활성화
1. Keycloak Admin Console 접속
2. Clients → pacs-server 선택
3. Settings 탭
   - Access Type: `confidential`
   - Service Accounts Enabled: `ON`
   - Authorization Enabled: `ON`
4. Service Account Roles 탭
   - realm-management → realm-admin 역할 할당

#### Realm 설정
1. Realm Settings
   - Access Token Lifespan: `5 minutes`
   - SSO Session Idle: `30 minutes`
   - SSO Session Max: `10 hours`

## 문제 해결 가이드

### 1. "Invalid client credentials" 에러

**원인**: Client secret 불일치

**해결**:
```bash
# Keycloak에서 client secret 확인
# Clients → pacs-server → Credentials 탭

# 환경 변수 업데이트
export KEYCLOAK_CLIENT_SECRET=<correct-secret>
```

---

### 2. "User account is disabled" 에러

**원인**: 사용자가 아직 승인되지 않음

**해결**:
```bash
# 관리자가 사용자 승인
PUT /api/users/{user_id}/approve
```

---

### 3. "Refresh token expired" 에러

**원인**: Refresh token 만료 (30분)

**해결**:
```javascript
// 재로그인 필요
if (error.message.includes('Refresh token expired')) {
  redirectToLogin();
}
```
