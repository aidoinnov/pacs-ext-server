## 🎯 작업 요약

### 구현된 기능
1. ✅ **Study/Series 할당 API** - 프로젝트에 DICOM 데이터 할당
2. ✅ **Study/Series 할당 해제 API** - 프로젝트에서 데이터 제거
3. ✅ **라우트 충돌 해결** - `/projects/*` 경로 통합
4. ✅ **E2E 테스트** - Dashboard에서 전체 흐름 검증
5. ✅ **프로젝트별 필터링** - Series 조회 시 할당 여부 확인

### 주요 엔드포인트
- `POST /api/projects/{id}/series/assign` - Series 할당
- `POST /api/projects/{id}/studies/assign` - Study 할당
- `DELETE /api/projects/{id}/series/{series_id}/unassign` - Series 해제
- `DELETE /api/projects/{id}/studies/{study_id}/unassign` - Study 해제
- `GET /api/project-data/{id}/studies` - 할당된 Study 목록
- `GET /api/project-data/{id}/studies/{study_id}/series` - 할당된 Series 목록

### 핵심 수정 사항
1. **라우트 통합**: 모든 `/projects/*` 라우트를 `project_controller`로 통합
2. **필터링 개선**: `find_series_by_project_and_study_id()` 메서드로 프로젝트별 필터링
3. **자동 할당 제거**: Series 할당 시 Study 자동 할당 제거
4. **테스트 추가**: Dashboard E2E 테스트로 할당/해제 검증

## 📊 데이터베이스 스키마

### 1. `project_data_study` (전역 Study 엔티티)

```sql
CREATE TABLE project_data_study (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    study_uid TEXT NOT NULL UNIQUE,  -- 전역 고유
    study_description TEXT,
    patient_id TEXT,
    patient_name TEXT,
    patient_birth_date DATE,
    study_date DATE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**특징**:
- Study는 전역 엔티티 (프로젝트 독립적)
- `study_uid`는 전역 고유 (UNIQUE 제약조건)
- 여러 프로젝트에서 동일한 Study를 참조 가능

### 2. `project_data_series` (Series 엔티티)

```sql
CREATE TABLE project_data_series (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    study_id INTEGER NOT NULL REFERENCES project_data_study(id) ON DELETE CASCADE,
    series_uid TEXT NOT NULL,
    series_description TEXT,
    modality TEXT,
    series_number INTEGER,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (study_id, series_uid)  -- Study 내에서 고유
);
```

**특징**:
- Series는 Study에 종속
- `(study_id, series_uid)` 조합이 고유
- Study 삭제 시 CASCADE로 자동 삭제

### 3. `project_data` (프로젝트-데이터 매핑)

```sql
CREATE TYPE resource_level_enum AS ENUM ('STUDY', 'SERIES', 'INSTANCE');

CREATE TABLE project_data (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES security_project(id) ON DELETE CASCADE,
    resource_level resource_level_enum NOT NULL DEFAULT 'STUDY',
    study_id INTEGER REFERENCES project_data_study(id) ON DELETE CASCADE,
    series_id INTEGER REFERENCES project_data_series(id) ON DELETE CASCADE,
    instance_id INTEGER REFERENCES project_data_instance(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**특징**:
- 프로젝트와 DICOM 데이터의 다대다 관계 관리
- `resource_level`로 할당 단위 구분 (STUDY, SERIES, INSTANCE)
- 계층적 참조 (study_id는 필수, series_id/instance_id는 선택적)

```
POST /api/projects/{project_id}/series/assign
```

```json
{
```

```json
{
  "success": true,
  "message": "Series 1.2.840.113619.2.1.2.322987881.716.1234567890.1 assigned to project successfully",
  "series_id": 456
}
```

**404 Not Found** - 프로젝트를 찾을 수 없음
```json
{
  "error": "Not Found",
  "message": "Project not found"
```

**409 Conflict** - 이미 할당된 Series
```json
{
  "error": "Already Exists",
  "message": "Series already assigned to this project"
}
```

**500 Internal Server Error** - 데이터베이스 오류
```json
{
  "error": "Database Error",
  "message": "..."
}
```

## 🔧 구현 세부사항

### 1. Series 할당 로직

```rust
pub async fn assign_series_to_project(
    &self,
    project_id: i32,
    request: AssignSeriesToProjectRequest,
) -> Result<AssignSeriesToProjectResponse, ServiceError> {
    // 1. 프로젝트 존재 확인
    self.project_service.get_project(project_id).await?;

    // 2. Study 조회 또는 생성
    let study = match self.project_data_service.get_study_by_uid(project_id, &request.study_uid).await {
        Ok(study) => study,
        Err(ServiceError::NotFound(_)) => {
            // Study 생성 로직
            ...
        }
        Err(e) => return Err(e),
    };

    // 3. Series 조회 또는 생성
    let series = sqlx::query_as(
        "INSERT INTO project_data_series (study_id, series_uid, ...)
         VALUES ($1, $2, ...)
         ON CONFLICT (study_id, series_uid) DO UPDATE ...
         RETURNING ..."
    ).fetch_one(pool).await?;

    // 4. project_data에 매핑 추가
    let result = sqlx::query(
        "INSERT INTO project_data (project_id, resource_level, study_id, series_id)
         VALUES ($1, 'SERIES'::resource_level_enum, $2, $3)
         ON CONFLICT DO NOTHING
         RETURNING id"
    ).fetch_optional(pool).await?;

    // 5. 중복 확인
    if result.is_none() {
        return Err(ServiceError::AlreadyExists(...));
    }

    Ok(AssignSeriesToProjectResponse { ... })
}
```

### 2. Study 자동 생성

Series 할당 시 부모 Study가 없으면 자동으로 생성됩니다:

```sql
INSERT INTO project_data_study (study_uid, study_description)
VALUES ($1, $2)
ON CONFLICT (study_uid) DO UPDATE SET study_uid = EXCLUDED.study_uid
RETURNING id, study_uid, ...
```

**주의사항**:
- Study 정보가 최소한으로만 저장됨 (study_uid, study_description)
- 환자 정보 등은 나중에 Study 할당 API로 업데이트 가능

### 3. 중복 방지

`ON CONFLICT DO NOTHING` 사용:

```sql
INSERT INTO project_data (project_id, resource_level, study_id, series_id)
VALUES ($1, 'SERIES'::resource_level_enum, $2, $3)
ON CONFLICT DO NOTHING
RETURNING id
```

- 중복 시 `RETURNING id`가 NULL
- NULL 확인 후 409 Conflict 반환

   ```sql
   SELECT * FROM security_project WHERE id = 107;
   ```

**증상**: Series 할당 시 409 반환

**원인**: 이미 할당된 Series

**해결**:
1. 기존 할당 확인:
   ```sql
   SELECT * FROM project_data 
   WHERE project_id = 107 AND series_id = (
       SELECT id FROM project_data_series WHERE series_uid = '...'
   );
   ```

2. 필요 시 기존 할당 삭제:
   ```sql
   DELETE FROM project_data WHERE id = ...;
   ```

**증상**: 데이터베이스 오류

**원인**:
- FK 제약조건 위반
- NULL 제약조건 위반
- 데이터베이스 연결 오류

**해결**:

## 📊 성능 최적화

### 1. 중복 할당 체크

**기존**: `ON CONFLICT DO NOTHING RETURNING id` (NULL 반환 시 중복)

**개선**: `EXISTS` 쿼리로 사전 체크
```rust
let already_assigned: bool = sqlx::query_scalar(
    "SELECT EXISTS(
        SELECT 1 FROM project_data
        WHERE project_id = $1 AND series_id = $2
    )"
).fetch_one(pool).await?;

if already_assigned {
    return Err(ServiceError::AlreadyExists(...));
}
```

**장점**: 명확한 에러 메시지, 불필요한 INSERT 방지

## 🎯 향후 개선 사항

1. **트랜잭션 추가**: 할당/해제 작업을 트랜잭션으로 묶기

3. **할당 이력**: 누가 언제 할당/해제했는지 기록
4. **권한 검증**: 프로젝트 관리자만 할당/해제 가능하도록 제한
