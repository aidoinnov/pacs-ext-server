### 1. TimePoint API - Study Instance UID 지원

**목적**: DICOM Study Instance UID를 사용하여 Study를 TimePoint에 할당/해제할 수 있도록 개선

**변경 파일**:

- `pacs-server/src/domain/services/timepoint_service.rs`
- `pacs-server/src/domain/repositories/project_data_repository.rs`
- `pacs-server/src/main.rs`

**주요 기능**:
- ✅ `study_instance_uids` 필드 추가
- ✅ Study UID → Study ID 자동 변환
- ✅ 기존 `study_ids` 방식과 호환

**사용 예시**:
```json
POST /api/timepoints/121/studies
{
  "study_instance_uids": [
    "1.3.6.1.4.1.14519.5.2.1.6655.2359.305690637242184753624524107418"
  ]
}
```

**주요 기능**:

**응답 예시**:

### 4. Rust Arc Blanket Implementation

**목적**: `Arc<T>`가 trait `T`를 구현하도록 하여 의존성 주입 문제 해결

**변경 파일**:
- `pacs-server/src/domain/repositories/project_data_repository.rs`

**주요 기능**:
- ✅ `Arc<ProjectDataRepositoryImpl>`이 `ProjectDataRepository` trait 구현
- ✅ 모든 trait 메서드를 Arc를 통해 위임
- ✅ 타입 안전성 유지

**구현 예시**:
```rust
#[async_trait]
impl<T: ProjectDataRepository + ?Sized> ProjectDataRepository for Arc<T> {
    async fn find_study_by_uid(...) -> Result<...> {
        (**self).find_study_by_uid(...).await
    }
}
```

### N+1 쿼리 문제

Subject API에서 각 Subject마다 TimePoint를 별도로 조회하는 N+1 문제가 있습니다.

**현재 구현**:
```rust
for subject in &mut subjects {
    let timepoints = query_timepoints(subject.id).await?;
    subject.timepoints = Some(timepoints);
}
```

**향후 개선 방안**:
- JOIN 쿼리 사용
- 페이지네이션 적용
- 선택적 로딩 (`include_timepoints` 파라미터)
