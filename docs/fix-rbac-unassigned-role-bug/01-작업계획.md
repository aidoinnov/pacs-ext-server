# RBAC Unassigned Role 버그 수정 작업 계획

## 📋 작업 개요

**작업명**: RBAC Unassigned 상태 사용자 역할 할당 버그 수정  
**브랜치**: `fix/rbac-unassigned-role-assignment-bug`  
**작업일**: 2025-11-10  
**담당자**: AIDO Team

---

## 🎯 작업 목표

사용자가 프로젝트에 이미 참여중이지만 `role_id = NULL` (Unassigned 상태)인 경우, 역할 할당 및 멤버 추가 API가 실패하는 버그를 수정한다.

---

## 🐛 문제 정의

### 버그 1: 역할 할당 API 실패
- **API**: `PUT /api/projects/{project_id}/users/{user_id}/role`
- **증상**: 사용자가 프로젝트에 참여중이지만 `role_id = NULL`인 경우 역할 할당 실패
- **에러**: "User is not a member of this project" 또는 중복 INSERT 에러

### 버그 2: 멤버 추가 API 실패
- **API**: `POST /api/projects/{project_id}/members`
- **증상**: 사용자가 프로젝트에 참여중이지만 `role_id = NULL`인 경우 멤버 추가 실패
- **에러**: `409 Conflict - "User is already a member of this project"`

---

## 🔍 원인 분석

### 데이터베이스 상태 불일치
- **논리적 상태**: Unassigned (역할 없음)
- **물리적 상태**: `security_user_project` 테이블에 레코드 존재, `role_id = NULL`

### 기존 로직의 문제점
1. **역할 할당 API**: 멤버십 존재 여부만 확인하고 INSERT 시도 → 중복 에러
2. **멤버 추가 API**: 멤버십 존재 시 무조건 에러 반환 → 역할 업데이트 불가

---

## 📐 해결 방안

### 접근 방식
**"이미 존재한다면 새로 추가하지 않고 기존 레코드를 업데이트"**

### 구현 전략
1. 사용자-프로젝트 참여 상태 조회
2. **이미 참여중인 경우**: 기존 레코드의 `role_id` UPDATE
3. **참여중이 아닌 경우**: 새로운 참여 레코드 INSERT
4. 트랜잭션으로 원자성 보장
5. 로깅 추가로 디버깅 용이성 향상
