# Subject 자동 생성 - 작업 계획

## 📌 작업 배경

### 문제점
1. **Subject 수동 생성의 불편함**
   - Study를 프로젝트에 할당할 때마다 Subject를 수동으로 생성해야 함
   - Patient ID가 같은 Study들을 일일이 연결해야 함
   - 사용자 경험이 좋지 않음

2. **데이터 불일치**
   - `project_data_study` 테이블에 `patient_id`가 NULL인 경우가 많음
   - DB에만 의존하여 PACS Archive의 메타데이터를 활용하지 못함
   - Subject 자동 생성이 실패하는 경우 발생

3. **기존 데이터 처리**
   - 이미 할당된 Study들에 대한 Subject가 없음
   - 수동으로 생성하기에는 데이터가 너무 많음 (375개 프로젝트)

## 🎯 작업 목표

### 1단계: Subject 자동 생성 기능 구현
- [x] Study 할당 시 Patient ID 기반 Subject 자동 생성
- [x] 중복 방지 (기존 Subject 재사용)
- [x] API 단순화 (patient_id 등 불필요한 필드 제거)

### 2단계: PACS Archive 연동
- [x] QIDO-RS를 통한 메타데이터 조회
- [x] DICOM 태그 파싱 (PatientID, PatientName, StudyDescription)
- [x] DB에 자동 업데이트 (UPSERT)

### 3단계: Subject Code 생성 규칙 정립
- [x] Patient ID가 있는 경우: Patient ID 사용
- [x] Patient ID가 없는 경우: A-001, A-002, ... 형식으로 자동 생성
- [x] 중복 시 접미사 추가 (P12345_1, P12345_2, ...)

### 4단계: 마이그레이션 도구 개발
- [x] Python 스크립트 작성
- [x] Dry-run 모드 지원
- [x] Rust 코드와 동일한 로직 적용
- [x] 375개 프로젝트 테스트
