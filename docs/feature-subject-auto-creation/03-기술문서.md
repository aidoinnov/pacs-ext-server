## 🔧 핵심 로직

### 1. DICOM 메타데이터 추출

**DICOM 태그 매핑**:
| DICOM Tag | 이름 | JSON Path | 설명 |
|-----------|------|-----------|------|
| (0010,0020) | PatientID | `["00100020"]["Value"][0]` | 환자 ID |
| (0010,0010) | PatientName | `["00100010"]["Value"][0]["Alphabetic"]` | 환자 이름 |
| (0008,1030) | StudyDescription | `["00081030"]["Value"][0]` | Study 설명 |

**코드 예시**:
```rust
let patient_id = study_json.get("00100020")
    .and_then(|v| v.get("Value"))
    .and_then(|v| v.as_array())
    .and_then(|arr| arr.first())
    .and_then(|v| v.as_str())
    .map(|s| s.to_string());
```

### 2. Subject Code 생성 규칙

#### 규칙 1: Patient ID가 있는 경우
```
기본: Patient ID 그대로 사용
예시: P12345

중복 시: 접미사 추가
예시: P12345_1, P12345_2, P12345_3, ...
```

#### 규칙 2: Patient ID가 없는 경우
```
형식: {알파벳}-{3자리 숫자}
범위: A-001 ~ Z-999 (총 26,000개)

예시:
  A-001, A-002, ..., A-999
  B-001, B-002, ..., B-999
  C-001, ...
```

**구현 코드**:
```rust
async fn generate_auto_subject_code(
    &self,
    project_id: i32,
) -> Result<String, ServiceError> {
    for prefix_char in 'A'..='Z' {
        for num in 1..=999 {
            let code = format!("{}-{:03}", prefix_char, num);
            
            if !self.subject_code_exists(project_id, &code).await? {
                return Ok(code);
            }
        }
    }
    
    Err(ServiceError::InternalError(
        "Failed to generate unique subject code".to_string(),
    ))
}
```

### 3. DB UPSERT 로직

**SQL**:
```sql
INSERT INTO project_data_study (
    study_uid, 
    study_description, 
    patient_id, 
    patient_name
)
VALUES ($1, $2, $3, $4)
ON CONFLICT (study_uid) DO UPDATE
SET 
    patient_id = COALESCE(EXCLUDED.patient_id, project_data_study.patient_id),
    patient_name = COALESCE(EXCLUDED.patient_name, project_data_study.patient_name),
    study_description = COALESCE(EXCLUDED.study_description, project_data_study.study_description),
    updated_at = CURRENT_TIMESTAMP
```

**특징**:
- `COALESCE`: NULL이 아닌 값 우선 사용
- 기존 데이터 보존 (덮어쓰지 않음)
- `updated_at` 자동 갱신

### 4. Subject 중복 방지

**중복 체크 쿼리**:
```sql
SELECT EXISTS(
    SELECT 1 FROM project_subject
    WHERE project_id = $1 AND patient_id = $2
)
```

**로직**:
1. Patient ID로 기존 Subject 검색
2. 존재하면 → 재사용 (새로 생성하지 않음)
3. 없으면 → 새로 생성

### project_subject
```sql
CREATE TABLE project_subject (
    id SERIAL PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES security_project(id),
    subject_code VARCHAR(255) NOT NULL,  -- ✅ 자동 생성
    patient_id VARCHAR(255),             -- ✅ PACS에서 가져옴
    patient_name VARCHAR(255),
    patient_birth_date DATE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(project_id, subject_code)
);

CREATE INDEX idx_project_subject_patient_id ON project_subject(project_id, patient_id);
```

### project_data
```sql
CREATE TABLE project_data (
    id SERIAL PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES security_project(id),
    resource_level resource_level_enum NOT NULL,
    study_id INTEGER REFERENCES project_data_study(id),
    series_id INTEGER REFERENCES project_data_series(id),

    UNIQUE(project_id, resource_level, study_id, series_id, instance_id)

```

## 🔄 처리 흐름

### 정상 케이스 (Patient ID 있음)
```
1. Study 할당 요청
   ↓
2. PACS Archive 조회 (QIDO-RS)
   ↓
3. Patient ID 추출: "P12345"
   ↓
4. DB에 Study 정보 UPSERT
   ↓
5. 기존 Subject 검색 (Patient ID: "P12345")
   ↓
6. 없으면 → Subject 생성 (subject_code: "P12345")
   ↓
7. project_data에 매핑 추가
   ↓
8. 완료
```

### 예외 케이스 (Patient ID 없음)
```
1. Study 할당 요청
   ↓
2. PACS Archive 조회 (QIDO-RS)
   ↓
3. Patient ID 없음 (NULL)
   ↓
4. DB에 Study 정보 UPSERT (patient_id: NULL)
   ↓
5. Subject 자동 생성 건너뜀
   ↓
6. project_data에 매핑 추가
   ↓
7. 완료 (Subject 없이)
```

**Note**: Patient ID가 없는 경우는 마이그레이션 도구로 별도 처리

### PACS 조회 실패 케이스
```
1. Study 할당 요청
   ↓
2. PACS Archive 조회 시도
   ↓
3. 실패 (네트워크 오류, 타임아웃 등)
   ↓
4. 경고 로그 출력
   ↓
5. DB에서 Study 조회 (기존 데이터 사용)
   ↓
6. 계속 진행 (Fallback)
```

## 📝 로깅

### 로그 레벨
- `INFO`: 정상 동작
- `WARN`: PACS 조회 실패 (Fallback 동작)
- `ERROR`: 치명적 오류

### 로그 예시
```
[INFO] Assigning study 1.2.840... to project 1
[INFO] Fetched study metadata from PACS Archive
[INFO] Created subject P12345 for project 1
[WARN] Failed to fetch study metadata from PACS: timeout
[ERROR] Failed to create subject: database error
```
