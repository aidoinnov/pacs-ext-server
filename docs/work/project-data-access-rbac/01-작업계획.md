## 🔧 기술적 고려사항

### 1. 테이블 스키마 설계

**계층적 접근 제어**:
- `resource_level`: STUDY, SERIES, INSTANCE
- `study_id`: Study 레벨 접근 제어
- `series_id`: Series 레벨 접근 제어
- `instance_id`: Instance 레벨 접근 제어

**접근 권한 상태**:
- `APPROVED`: 승인됨
- `DENIED`: 거부됨
- `PENDING`: 대기 중

**접근 범위**:
- `FULL`: 전체 접근
- `LIMITED`: 제한된 접근
- `READ_ONLY`: 읽기 전용

### 2. 제약 조건

**UNIQUE 제약**:
```sql
UNIQUE (project_id, user_id, study_id, series_id, instance_id)
```
- 동일한 사용자가 동일한 리소스에 대해 중복 권한을 가질 수 없음
- NULL 값은 UNIQUE 제약에서 제외됨 (PostgreSQL 특성)

### 3. 인덱스 전략

**성능 최적화**:
- 단일 컬럼 인덱스: 자주 조회되는 컬럼 (project_id, user_id, status)
- 복합 인덱스: 함께 조회되는 컬럼 (project_id + user_id)
- 부분 인덱스: NULL이 아닌 경우만 인덱싱 (WHERE study_id IS NOT NULL)

### 4. 하위 호환성

**기존 코드와의 호환성**:
- `project_data_id` 필드는 제거하지 않음 (기존 코드 호환성)
- 새로운 필드는 모두 NULL 허용 또는 DEFAULT 값 설정
- 마이그레이션은 기존 데이터에 영향을 주지 않음
