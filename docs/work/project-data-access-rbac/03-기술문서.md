# [RBAC 기능 보완] 프로젝트 데이터 접근 제한 설정 - 기술 문서

## 📅 작성 일자
2025-11-12

## 🎯 기능 개요

### 기본 권한 모델
- **프로젝트 멤버** → 프로젝트의 **모든 데이터** 접근 가능 (기본)

### 추가 제한 기능
- 프로젝트 멤버지만, **특정 데이터만** 접근하도록 제한
- 승인/거부 워크플로우 지원
- 계층적 접근 제어 (Study/Series/Instance)
- 읽기 전용, 임시 접근 등 세밀한 제어

## 🏗️ 데이터베이스 스키마

### `project_data_access` 테이블

#### 테이블 구조

```sql
CREATE TABLE IF NOT EXISTS project_data_access (
    -- Primary key
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    
    -- User reference
    user_id INTEGER NOT NULL REFERENCES security_user(id) ON DELETE CASCADE,
    
    -- Project reference
    project_id INTEGER NOT NULL REFERENCES security_project(id) ON DELETE CASCADE,
    
    -- Hierarchical access control (Study → Series → Instance)
    resource_level resource_level_enum NOT NULL DEFAULT 'STUDY',
    study_id INTEGER REFERENCES project_data_study(id) ON DELETE CASCADE,
    series_id INTEGER REFERENCES project_data_series(id) ON DELETE CASCADE,
    instance_id INTEGER REFERENCES project_data_instance(id) ON DELETE CASCADE,
    
    -- Legacy field for backward compatibility
    project_data_id INTEGER,
    
    -- Access status
    status data_access_status_enum NOT NULL DEFAULT 'PENDING',
    
    -- Request information
    requested_at TIMESTAMPTZ,
    requested_by INTEGER REFERENCES security_user(id),
    
    -- Review information
    reviewed_at TIMESTAMPTZ,
    reviewed_by INTEGER REFERENCES security_user(id),
    review_note TEXT,
    
    -- Grant information
    granted_by INTEGER REFERENCES security_user(id),
    granted_at TIMESTAMPTZ,
    
    -- Institution-based access control
    user_institution_id INTEGER REFERENCES security_institution(id),
    data_institution_id INTEGER REFERENCES project_data_institution(id),
    
    -- Access scope
    access_scope VARCHAR(50) DEFAULT 'FULL',
    
    -- Expiration
    expires_at TIMESTAMPTZ,
    
    -- Timestamps
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- Unique constraint
    UNIQUE (project_id, user_id, study_id, series_id, instance_id)
);
```

#### ENUM 타입

**`resource_level_enum`**: 리소스 레벨
```sql
CREATE TYPE resource_level_enum AS ENUM ('STUDY', 'SERIES', 'INSTANCE');
```

**`data_access_status_enum`**: 접근 권한 상태
```sql
CREATE TYPE data_access_status_enum AS ENUM ('APPROVED', 'DENIED', 'PENDING');
```

#### 인덱스 (총 9개)

**단일 컬럼 인덱스**:
```sql
CREATE INDEX idx_project_data_access_project ON project_data_access(project_id);
CREATE INDEX idx_project_data_access_user ON project_data_access(user_id);
CREATE INDEX idx_project_data_access_status ON project_data_access(status);
```

**부분 인덱스** (NULL이 아닌 경우만):
```sql
CREATE INDEX idx_project_data_access_study 
    ON project_data_access(study_id) 
    WHERE study_id IS NOT NULL;

CREATE INDEX idx_project_data_access_series 
    ON project_data_access(series_id) 
    WHERE series_id IS NOT NULL;

CREATE INDEX idx_project_data_access_instance 
    ON project_data_access(instance_id) 
    WHERE instance_id IS NOT NULL;

CREATE INDEX idx_project_data_access_expires 
    ON project_data_access(expires_at) 
    WHERE expires_at IS NOT NULL;
```

**복합 인덱스**:
```sql
CREATE INDEX idx_project_data_access_project_user 
    ON project_data_access(project_id, user_id);

CREATE INDEX idx_project_data_access_resource 
    ON project_data_access(resource_level, study_id, series_id, instance_id)
    WHERE resource_level IS NOT NULL;
```

#### 트리거

**`updated_at` 자동 업데이트**:
```sql
CREATE TRIGGER trigger_update_project_data_access_updated_at
    BEFORE UPDATE ON project_data_access
    FOR EACH ROW
    EXECUTE FUNCTION update_project_data_access_updated_at();
```

## 🔐 계층적 접근 제어

### 3단계 계층 구조

```
Study (연구)
  └─ Series (시리즈)
      └─ Instance (이미지)
```

### 접근 제어 레벨

#### 1. Study 레벨 (`resource_level = 'STUDY'`)
- **제어 범위**: 전체 Study
- **필수 필드**: `study_id`
- **선택 필드**: `series_id = NULL`, `instance_id = NULL`

**예시**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id, status
) VALUES (
    123, 90, 'STUDY', 456, 'APPROVED'
);
```
→ 사용자 123은 Study 456 전체에 접근 가능

#### 2. Series 레벨 (`resource_level = 'SERIES'`)
- **제어 범위**: 특정 Series
- **필수 필드**: `study_id`, `series_id`
- **선택 필드**: `instance_id = NULL`

**예시**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id, series_id, status
) VALUES (
    123, 90, 'SERIES', 456, 789, 'APPROVED'
);
```
→ 사용자 123은 Study 456의 Series 789만 접근 가능

#### 3. Instance 레벨 (`resource_level = 'INSTANCE'`)
- **제어 범위**: 특정 Instance (이미지)
- **필수 필드**: `study_id`, `series_id`, `instance_id`

**예시**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id, series_id, instance_id, status
) VALUES (
    123, 90, 'INSTANCE', 456, 789, 1011, 'APPROVED'
);
```
→ 사용자 123은 Study 456의 Series 789의 Instance 1011만 접근 가능

## 🔄 접근 권한 워크플로우

### 1. 접근 요청 (Request)

**사용자가 데이터 접근을 요청**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, requested_at, requested_by
) VALUES (
    123, 90, 'STUDY', 456,
    'PENDING', NOW(), 123
);
```

**상태**: `PENDING` (대기 중)

### 2. 검토 (Review)

**관리자가 요청을 검토**:
```sql
UPDATE project_data_access
SET 
    reviewed_at = NOW(),
    reviewed_by = 999,  -- 관리자 ID
    review_note = '검토 완료: 승인 가능'
WHERE id = 1;
```

### 3. 승인 (Approve)

**관리자가 요청을 승인**:
```sql
UPDATE project_data_access
SET 
    status = 'APPROVED',
    granted_at = NOW(),
    granted_by = 999  -- 관리자 ID
WHERE id = 1;
```

**상태**: `APPROVED` (승인됨)

### 4. 거부 (Deny)

**관리자가 요청을 거부**:
```sql
UPDATE project_data_access
SET 
    status = 'DENIED',
    reviewed_at = NOW(),
    reviewed_by = 999,
    review_note = '접근 권한 없음'
WHERE id = 1;
```

**상태**: `DENIED` (거부됨)

## 🎛️ 접근 범위 (Access Scope)

### 접근 범위 종류

#### 1. `FULL` (전체 접근)
- **읽기**: ✅
- **쓰기**: ✅
- **삭제**: ✅

#### 2. `LIMITED` (제한된 접근)
- **읽기**: ✅
- **쓰기**: ⚠️ (일부만)
- **삭제**: ❌

#### 3. `READ_ONLY` (읽기 전용)
- **읽기**: ✅
- **쓰기**: ❌
- **삭제**: ❌

### 사용 예시

**읽기 전용 접근**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, access_scope
) VALUES (
    123, 90, 'STUDY', 456,
    'APPROVED', 'READ_ONLY'
);
```

## ⏰ 임시 접근 (Expiration)

### 만료 시간 설정

**7일 동안만 접근 허용**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, access_scope, expires_at
) VALUES (
    123, 90, 'STUDY', 456,
    'APPROVED', 'FULL',
    NOW() + INTERVAL '7 days'
);
```

**30일 동안만 접근 허용**:
```sql
expires_at = NOW() + INTERVAL '30 days'
```

### 만료 확인 쿼리

**만료된 접근 권한 조회**:
```sql
SELECT * FROM project_data_access
WHERE expires_at IS NOT NULL 
  AND expires_at < NOW()
  AND status = 'APPROVED';
```

## 🏥 기관 기반 접근 제어

### 기관별 데이터 분리

**사용자 기관과 데이터 기관 매칭**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, 
    user_institution_id,  -- 사용자 소속 기관
    data_institution_id   -- 데이터 소속 기관
) VALUES (
    123, 90, 'STUDY', 456,
    'APPROVED',
    10,  -- A병원
    10   -- A병원 데이터만 접근
);
```

### 다기관 공동 연구 시나리오

```sql
-- A병원 연구원 → A병원 데이터만
INSERT INTO project_data_access (user_id, project_id, study_id, status, user_institution_id, data_institution_id)
VALUES (101, 90, 456, 'APPROVED', 10, 10);

-- B병원 연구원 → B병원 데이터만
INSERT INTO project_data_access (user_id, project_id, study_id, status, user_institution_id, data_institution_id)
VALUES (201, 90, 789, 'APPROVED', 20, 20);

-- 책임연구원 → 모든 기관 데이터 (제약 없음)
-- project_data_access 레코드 없음 = 전체 접근
```

## 🔍 사용 시나리오

### 시나리오 1: 민감한 환자 데이터 제한

**상황**: VIP 환자 데이터는 특정 연구원만 접근 가능

**구현**:
```sql
-- VIP 환자 Study에 대한 접근 제한
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, access_scope, review_note
) VALUES (
    123, 90, 'STUDY', 456,
    'APPROVED', 'READ_ONLY', 'VIP 환자 - 읽기 전용'
);
```

### 시나리오 2: 단계별 데이터 공개

**상황**: 임상시험 초기에는 일부 데이터만 공개, 승인 후 전체 공개

**구현**:
```sql
-- 초기: 일부 Study만 접근
INSERT INTO project_data_access (user_id, project_id, study_id, status)
VALUES (123, 90, 456, 'APPROVED');

-- 승인 후: 모든 Study 접근 (레코드 삭제)
DELETE FROM project_data_access WHERE user_id = 123 AND project_id = 90;
```

### 시나리오 3: 임시 협력 연구원

**상황**: 외부 협력 연구원에게 30일 동안만 접근 허용

**구현**:
```sql
INSERT INTO project_data_access (
    user_id, project_id, resource_level, study_id,
    status, access_scope, expires_at
) VALUES (
    123, 90, 'STUDY', 456,
    'APPROVED', 'READ_ONLY',
    NOW() + INTERVAL '30 days'
);
```

## 🎯 요약

### 핵심 기능

1. ✅ **계층적 접근 제어**: Study/Series/Instance 레벨
2. ✅ **승인 워크플로우**: PENDING → APPROVED/DENIED
3. ✅ **접근 범위 제어**: FULL/LIMITED/READ_ONLY
4. ✅ **임시 접근**: expires_at으로 만료 시간 설정
5. ✅ **기관 기반 제어**: 다기관 공동 연구 지원

### 기본 원칙

- **프로젝트 멤버** = 전체 데이터 접근 (기본)
- **`project_data_access` 레코드 존재** = 특정 데이터만 접근 (제한)
- **레코드 없음** = 제한 없음 (전체 접근)

### 성능 최적화

- 9개 인덱스로 빠른 조회
- 부분 인덱스로 NULL 값 제외
- 복합 인덱스로 자주 사용되는 쿼리 최적화
