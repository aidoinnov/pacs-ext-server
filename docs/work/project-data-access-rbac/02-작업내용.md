### 2. 마이그레이션 파일 생성 ✅

**파일**: `pacs-server/migrations/028_create_project_data_access.sql`

**작업 내용**:

1. **`project_data_access` 테이블 생성**
   ```sql
   CREATE TABLE IF NOT EXISTS project_data_access (
       -- Primary key
       id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
       
       -- User reference
       user_id INTEGER NOT NULL REFERENCES security_user(id) ON DELETE CASCADE,
       
       -- Project reference
       project_id INTEGER NOT NULL REFERENCES security_project(id) ON DELETE CASCADE,
       
       -- Hierarchical access control (Study → Series → Instance)
       resource_level resource_level_enum NOT NULL DEFAULT 'STUDY',
       study_id INTEGER REFERENCES project_data_study(id) ON DELETE CASCADE,
       series_id INTEGER REFERENCES project_data_series(id) ON DELETE CASCADE,
       instance_id INTEGER REFERENCES project_data_instance(id) ON DELETE CASCADE,
       
       -- Legacy field for backward compatibility
       project_data_id INTEGER,
       
       -- Access status
       status data_access_status_enum NOT NULL DEFAULT 'PENDING',
       
       -- Request/Review/Grant information
       requested_at TIMESTAMPTZ,
       requested_by INTEGER REFERENCES security_user(id),
       reviewed_at TIMESTAMPTZ,
       reviewed_by INTEGER REFERENCES security_user(id),
       review_note TEXT,
       granted_by INTEGER REFERENCES security_user(id),
       granted_at TIMESTAMPTZ,
       
       -- Institution-based access control
       user_institution_id INTEGER REFERENCES security_institution(id),
       data_institution_id INTEGER REFERENCES project_data_institution(id),
       
       -- Access scope
       access_scope VARCHAR(50) DEFAULT 'FULL',
       
       -- Expiration
       expires_at TIMESTAMPTZ,
       
       -- Timestamps
       created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
       updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
       
       -- Unique constraint
       UNIQUE (project_id, user_id, study_id, series_id, instance_id)
   );
   ```

2. **인덱스 생성** (총 9개)
   - 단일 컬럼 인덱스:
     - `idx_project_data_access_project`: project_id
     - `idx_project_data_access_user`: user_id
     - `idx_project_data_access_status`: status
   
   - 부분 인덱스 (NULL이 아닌 경우만):
     - `idx_project_data_access_study`: study_id
     - `idx_project_data_access_series`: series_id
     - `idx_project_data_access_instance`: instance_id
     - `idx_project_data_access_expires`: expires_at
   
   - 복합 인덱스:
     - `idx_project_data_access_project_user`: (project_id, user_id)
     - `idx_project_data_access_resource`: (resource_level, study_id, series_id, instance_id)

3. **트리거 생성**
   ```sql
   CREATE TRIGGER trigger_update_project_data_access_updated_at
       BEFORE UPDATE ON project_data_access
       FOR EACH ROW
       EXECUTE FUNCTION update_project_data_access_updated_at();
   ```

4. **코멘트 추가**
   - 테이블 및 주요 컬럼에 대한 설명 추가

## 🔧 기술적 세부사항

### 테이블 스키마 설계

**계층적 접근 제어**:
- `resource_level`: STUDY, SERIES, INSTANCE
- `study_id`: Study 레벨 접근 제어 (NULL 허용)
- `series_id`: Series 레벨 접근 제어 (NULL 허용)
- `instance_id`: Instance 레벨 접근 제어 (NULL 허용)

**접근 권한 상태**:
- `APPROVED`: 승인됨
- `DENIED`: 거부됨
- `PENDING`: 대기 중 (기본값)

**접근 범위**:
- `FULL`: 전체 접근 (기본값)
- `LIMITED`: 제한된 접근
- `READ_ONLY`: 읽기 전용

### 제약 조건

**UNIQUE 제약**:
```sql
UNIQUE (project_id, user_id, study_id, series_id, instance_id)
```
- 동일한 사용자가 동일한 리소스에 대해 중복 권한을 가질 수 없음
- NULL 값은 UNIQUE 제약에서 제외됨 (PostgreSQL 특성)

### 인덱스 전략

**성능 최적화**:
- 단일 컬럼 인덱스: 자주 조회되는 컬럼 (project_id, user_id, status)
- 복합 인덱스: 함께 조회되는 컬럼 (project_id + user_id)
- 부분 인덱스: NULL이 아닌 경우만 인덱싱 (WHERE study_id IS NOT NULL)
