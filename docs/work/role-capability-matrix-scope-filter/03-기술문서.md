## 🔍 핵심 기술 구현

### 1. 동적 SQL 쿼리 생성

#### 구현 방식

**Repository Layer** (`capability_repository_impl.rs`):

```rust
pub async fn get_global_role_capability_matrix(
    &self,
    scope: Option<&str>,
) -> Result<(Vec<Role>, Vec<Capability>, Vec<(i32, i32)>), sqlx::Error> {
    // WHERE 절 동적 생성
    let where_clause = if let Some(scope_filter) = scope {
        if !scope_filter.trim().is_empty() {
            format!("WHERE scope = '{}'", scope_filter)
        } else {
            String::new()
        }
    } else {
        String::new()
    };

    // 역할 조회 쿼리
    let roles_query = format!(
        "SELECT id, name, description, scope
         FROM security_role
         {}
         ORDER BY name",
        where_clause
    );

    let roles = sqlx::query_as::<_, Role>(&roles_query)
        .fetch_all(&self.pool)
        .await?;

    // ... capabilities 및 assignments 조회
}
```

#### 생성되는 SQL 쿼리

1. **scope 파라미터 없음**:
   ```sql
   SELECT id, name, description, scope
   FROM security_role
   ORDER BY name
   ```

2. **scope=GLOBAL**:
   ```sql
   SELECT id, name, description, scope
   FROM security_role
   WHERE scope = 'GLOBAL'
   ORDER BY name
   ```

3. **scope=PROJECT**:
   ```sql
   SELECT id, name, description, scope
   FROM security_role
   WHERE scope = 'PROJECT'
   ORDER BY name
   ```

### 2. 페이지네이션과 Scope 필터 조합

#### 기존 문제점

```rust
// ❌ 기존 코드 - 하드코딩된 조건
let mut where_conditions = vec!["scope = 'GLOBAL'".to_string()];

if let Some(scope_filter) = scope {
    if !scope_filter.trim().is_empty() {
        param_count += 1;
        where_conditions.push(format!("scope = ${}", param_count));
        // ← 충돌! 이미 scope = 'GLOBAL'이 있는데 또 추가
    }
}
```

#### 개선된 구현

```rust
// ✅ 개선된 코드 - 동적 조건 생성
let mut where_conditions = Vec::new();  // 빈 벡터로 시작

// scope 필터가 있을 때만 조건 추가
if let Some(scope_filter) = scope {
    if !scope_filter.trim().is_empty() {
        param_count += 1;
        where_conditions.push(format!("scope = ${}", param_count));
        scope_param = Some(scope_filter.to_string());
    }
}

// search 필터 처리
if let Some(search_term) = search {
    if !search_term.trim().is_empty() {
        param_count += 1;
        where_conditions.push(format!(
            "(name ILIKE ${} OR description ILIKE ${})",
            param_count, param_count
        ));
        search_param = Some(format!("%{}%", search_term));
    }
}

// WHERE 절 생성
let where_clause = if where_conditions.is_empty() {
    String::new()
} else {
    format!("WHERE {}", where_conditions.join(" AND "))
};
```

### 3. 타입 안전성 보장

#### Option<&str> vs Option<String>

**Use Case Layer**:
```rust
pub async fn get_global_matrix(
    &self,
    scope: Option<String>,  // ← 소유권을 가진 String
) -> Result<RoleCapabilityMatrixResponse, ServiceError> {
    let scope_ref = scope.as_deref();  // ← Option<&str>로 변환
    
    let (roles, capabilities, assignments) = self
        .capability_service
        .get_global_role_capability_matrix(scope_ref)
        .await?;
    // ...
}
```

**Service Layer**:
```rust
async fn get_global_role_capability_matrix(
    &self,
    scope: Option<&str>,  // ← 참조만 받음 (복사 방지)
) -> Result<(Vec<Role>, Vec<Capability>, Vec<(i32, i32)>), sqlx::Error>;
```

**이유**:
- Use Case는 HTTP 요청에서 받은 `String`을 소유
- Service/Repository는 참조만 필요 (불필요한 복사 방지)
- `as_deref()`로 `Option<String>` → `Option<&str>` 변환

## 🔒 보안 고려사항

### SQL Injection 방지

#### ❌ 취약한 코드 (사용하지 않음)
```rust
// 직접 문자열 삽입 - SQL Injection 위험!
let query = format!(
    "SELECT * FROM security_role WHERE scope = '{}'",
    scope  // ← 사용자 입력을 직접 삽입
);
```

#### ✅ 안전한 코드 (현재 구현)
```rust
// 방법 1: 제한된 값만 허용
let where_clause = if let Some(scope_filter) = scope {
    if scope_filter == "GLOBAL" || scope_filter == "PROJECT" {
        format!("WHERE scope = '{}'", scope_filter)
    } else {
        String::new()  // 잘못된 값은 무시
    }
} else {
    String::new()
};

// 방법 2: Prepared Statement 사용 (더 안전)
// 향후 개선 시 고려
```

### 현재 구현의 안전성

1. **제한된 입력 값**: scope는 "GLOBAL" 또는 "PROJECT"만 유효
2. **빈 문자열 처리**: 빈 문자열은 필터링하지 않음
3. **대소문자 구분**: 정확히 일치하는 경우만 필터링

## 📊 성능 고려사항

### 데이터베이스 쿼리 성능

#### 인덱스 활용

```sql
-- security_role 테이블의 scope 컬럼에 인덱스가 있다고 가정
CREATE INDEX idx_security_role_scope ON security_role(scope);
```

#### 쿼리 실행 계획

1. **scope 필터 있음**:
   - Index Scan on `idx_security_role_scope`
   - 빠른 조회 (O(log n))

2. **scope 필터 없음**:
   - Sequential Scan on `security_role`
   - 전체 테이블 스캔 (O(n))
   - 하지만 역할 개수가 적어서 성능 문제 없음

#### 측정된 성능

```
🔍 Database query time: 190.723625ms
```

- 8개 역할 조회 시 약 190ms
- 네트워크 지연 포함
- 실제 쿼리 실행 시간은 더 짧음 (< 10ms)

## 📝 향후 개선 사항

### 1. Prepared Statement 사용

현재는 문자열 포맷팅을 사용하지만, 향후 SQLx의 Prepared Statement를 사용하여 더 안전하게 개선 가능:

```rust
let roles = if let Some(scope_filter) = scope {
    sqlx::query_as::<_, Role>(
        "SELECT id, name, description, scope
         FROM security_role
         WHERE scope = $1
         ORDER BY name"
    )
    .bind(scope_filter)
    .fetch_all(&self.pool)
    .await?
} else {
    sqlx::query_as::<_, Role>(
        "SELECT id, name, description, scope
         FROM security_role
         ORDER BY name"
    )
    .fetch_all(&self.pool)
    .await?
};
```

### 2. Enum 타입 사용

scope 값을 문자열 대신 Enum으로 정의:

```rust
#[derive(Debug, Deserialize)]
#[serde(rename_all = "UPPERCASE")]
pub enum RoleScope {
    Global,
    Project,
}

#[derive(Deserialize)]
pub struct GlobalMatrixQuery {
    pub scope: Option<RoleScope>,
}
```

### 3. 캐싱 추가

역할 데이터는 자주 변경되지 않으므로 Redis 캐싱 추가 고려:

```rust
// 캐시 키: "role_matrix:scope:{scope}"
let cache_key = format!("role_matrix:scope:{}", scope.unwrap_or("all"));
```
