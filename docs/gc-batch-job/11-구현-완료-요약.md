## 🚀 사용 방법

### 빌드
```bash
cd pacs-server
cargo build --bin gc_runner
```

### 실행 (Dry-run)
```bash
# Job A: PENDING 타임아웃
./target/debug/gc_runner timeout-pending --grace-days 3 --batch-size 1000 --dry-run

# Job B: FAILED 정리
./target/debug/gc_runner cleanup-failed --grace-days 7 --batch-size 1000 --dry-run
```

### 실행 (실제)
```bash
# Job A
./target/debug/gc_runner timeout-pending --grace-days 3 --batch-size 1000

# Job B
./target/debug/gc_runner cleanup-failed --grace-days 7 --batch-size 1000
```

## 🎯 주요 개선사항

### 1. 트랜잭션 일관성
- 로그 기록 실패 시에도 GC 작업 계속 진행
- 각 작업을 독립적으로 처리

### 2. 멱등성 보장
- 중복 실행 시 안전하게 처리
- 이미 처리된 항목 재처리 안함

### 3. 경계값 처리
- Grace Period 정확히 일치하는 경우도 처리
- Batch Size 정확한 크기 준수

### 4. 동시 실행 방지
- PostgreSQL Advisory Lock 사용
- Job A (1001), Job B (1002) 독립적 락
- 커넥션 종료 시 자동 해제

### 5. file_size 기록
- S3 파일 삭제 전 크기 조회
- 용량 모니터링 및 비용 분석 가능
