# DICOM 전체 데이터 조회 권한 기능 작업 계획

## 📋 작업 개요

### 배경
현재 DICOM Gateway API는 `project_id` 파라미터가 필수이며, 프로젝트 멤버십과 Access Condition에 따라 데이터를 필터링합니다. 하지만 시스템 관리자나 특정 권한을 가진 사용자는 프로젝트 제약 없이 전체 DICOM 데이터를 조회할 필요가 있습니다.

### 요구사항
1. **`project_id` 파라미터를 옵셔널로 변경**
2. **전체 DICOM 데이터 조회 권한 추가**
   - 새로운 Permission 추가
   - 새로운 Capability 추가
   - 특정 Role에 Capability 할당
3. **권한 기반 데이터 조회**
   - 전체 데이터 조회 권한이 있으면: 모든 DICOM 데이터 조회 가능
   - 권한이 없으면: 기존과 동일 (project_id 필수, 프로젝트 멤버십 + Access Condition 적용)

## 🎯 기능 명세

### 1. Permission 추가

**새로운 Permission**:
- `category`: "DICOM 데이터 관리"
- `resource_type`: "DICOM"
- `action`: "READ_ALL"
- **의미**: 모든 프로젝트의 DICOM 데이터를 조회할 수 있는 권한

### 2. Capability 추가

**새로운 Capability**:
- `name`: "DICOM_GLOBAL_ACCESS"
- `display_name`: "DICOM 전체 접근"
- `display_label`: "Global"
- `description`: "모든 프로젝트의 DICOM 데이터 조회 권한"
- `category`: "DICOM 데이터 관리"
- `category_label`: "DICOM"

**Capability-Permission 매핑**:
- `DICOM_GLOBAL_ACCESS` → `DICOM:READ_ALL`

### 3. Role 할당

**기본 할당**:
- `SUPER_ADMIN` Role에 `DICOM_GLOBAL_ACCESS` Capability 할당

## 🔧 구현 범위

### 1. Database Migration

**파일**: `pacs-server/migrations/XXX_add_dicom_global_access.sql`

```sql
-- 1. Permission 추가
INSERT INTO security_permission (category, resource_type, action) VALUES
    ('DICOM 데이터 관리', 'DICOM', 'READ_ALL');

-- 2. Capability 추가
INSERT INTO security_capability (name, display_name, display_label, description, category, category_label) VALUES
    ('DICOM_GLOBAL_ACCESS', 'DICOM 전체 접근', 'Global', '모든 프로젝트의 DICOM 데이터 조회 권한', 'DICOM 데이터 관리', 'DICOM');

-- 3. Capability-Permission 매핑
INSERT INTO security_capability_mapping (capability_id, permission_id)
SELECT c.id, p.id
FROM security_capability c, security_permission p
WHERE c.name = 'DICOM_GLOBAL_ACCESS' 
  AND p.resource_type = 'DICOM' 
  AND p.action = 'READ_ALL';

-- 4. SUPER_ADMIN Role에 Capability 할당
INSERT INTO security_role_capability (role_id, capability_id)
SELECT r.id, c.id
FROM security_role r, security_capability c
WHERE r.name = 'SUPER_ADMIN' 
  AND c.name = 'DICOM_GLOBAL_ACCESS';
```

### 2. DICOM Gateway Controller 수정

**파일**: `pacs-server/src/presentation/controllers/dicom_gateway_controller.rs`

#### 변경 사항:

1. **`project_id` 검증 로직 수정**
   - 현재: `project_id` 또는 `check_assignment_for_project` 필수
   - 변경: 전체 데이터 조회 권한이 있으면 둘 다 옵셔널

2. **권한 확인 로직 추가**
   ```rust
   async fn has_global_dicom_access(user_id: i32, pool: &PgPool) -> bool {
       sqlx::query_scalar::<_, bool>(
           "SELECT EXISTS(
               SELECT 1 FROM security_user_project sup
               INNER JOIN security_role r ON sup.role_id = r.id
               INNER JOIN security_role_capability src ON r.id = src.role_id
               INNER JOIN security_capability c ON src.capability_id = c.id
               WHERE sup.user_id = $1 
                 AND c.name = 'DICOM_GLOBAL_ACCESS'
           )"
       )
       .bind(user_id)
       .fetch_one(pool)
       .await
       .unwrap_or(false)
   }
   ```

3. **`get_studies` 핸들러 수정**
   ```rust
   // 1. 사용자 인증
   let user_id = extract_user_id_from_request(&req, &jwt_service, &user_repo).await?;
   
   // 2. 전체 데이터 조회 권한 확인
   let has_global_access = has_global_dicom_access(user_id, project_data_repo.pool()).await;
   
   // 3. project_id 검증
   if !has_global_access && query.project_id.is_none() && query.check_assignment_for_project.is_none() {
       return HttpResponse::BadRequest().json(json!({
           "error": "project_id or check_assignment_for_project is required"
       }));
   }
   
   // 4. Access Condition 적용 (project_id가 있을 때만)
   let access_conditions = if let Some(pid) = query.project_id {
       access_condition_repo.find_by_project_id(pid).await.unwrap_or_default()
   } else {
       vec![]
   };
   
   // 5. QIDO 조회 (Access Condition 적용)
   let qido_result = qido.qido_studies_with_bearer(...).await?;
   
   // 6. RBAC 필터링
   let filtered = if has_global_access && query.project_id.is_none() {
       // 전체 데이터 조회 권한이 있고 project_id가 없으면 필터링 안 함
       qido_result
   } else {
       // 기존 RBAC 필터링 로직
       apply_rbac_filtering(qido_result, user_id, project_id, &evaluator).await
   };
   
   // 7. 할당 여부 확인 (check_assignment_for_project가 있을 때만)
   // ... 기존 로직 유지
   ```

4. **`get_series` 핸들러 수정**
   - `get_studies`와 동일한 로직 적용

## 📝 사용 시나리오

### 시나리오 1: 전체 데이터 조회 (권한 있음)

```json

  ...
]
```

## ⚠️ 주의사항

### 1. 보안
- **전체 데이터 조회 권한은 매우 강력한 권한**이므로 신중하게 할당
- SUPER_ADMIN Role에만 기본 할당
- 권한 확인 로직이 우회되지 않도록 주의

### 2. 성능
- 전체 데이터 조회 시 대량의 데이터가 반환될 수 있음
- QIDO 서버의 limit 파라미터 활용 권장
- 페이지네이션 고려

### 3. 하위 호환성
- 기존 `project_id` 파라미터 동작 100% 유지
- 기존 `check_assignment_for_project` 파라미터 동작 100% 유지
- 기존 API 호출에 영향 없음

## 🔍 검토 사항

### 1. Role 검토
- **SUPER_ADMIN**: ✅ DICOM_GLOBAL_ACCESS 할당
- **ADMIN**: ❓ 필요 시 할당 (검토 필요)
- **PROJECT_ADMIN**: ❌ 할당 안 함 (프로젝트 범위만)
- **USER**: ❌ 할당 안 함
- **VIEWER**: ❌ 할당 안 함

### 2. Capability 검토
- **이름**: `DICOM_GLOBAL_ACCESS` (명확함)
- **카테고리**: "DICOM 데이터 관리" (적절함)
- **Permission 매핑**: `DICOM:READ_ALL` (명확함)

### 3. 구현 방식 검토
- **권한 확인 위치**: 핸들러 초반 (적절함)
- **필터링 우회**: 권한이 있고 project_id가 없을 때만 (안전함)
- **에러 처리**: 권한 없고 project_id 없으면 400 (명확함)
