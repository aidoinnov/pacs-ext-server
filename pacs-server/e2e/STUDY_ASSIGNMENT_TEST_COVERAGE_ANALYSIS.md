### 🔴 **중요도: 높음** (추가 권장)

#### 1. **데이터 변경 후 캐시 무효화 테스트**
- **설명**: Study 할당 후 프로젝트 데이터 목록의 ETag가 변경되는지 검증
- **이유**: Project Data Access API는 ETag 캐시를 사용하므로, Study 할당 시 캐시 무효화가 중요
- **테스트 시나리오**:
  1. 프로젝트 데이터 목록 조회 → ETag1 획득
  2. Study 할당
  3. 프로젝트 데이터 목록 재조회 → ETag2 획득
  4. ETag1 ≠ ETag2 검증
  5. 이전 ETag로 요청 시 200 OK (새 데이터) 반환 확인

#### 2. **Series 할당 테스트**
- **설명**: Series 할당 API 검증
- **이유**: Study 할당과 유사하지만 Series는 Study의 하위 리소스
- **테스트 시나리오**:
  1. Series 할당 성공
  2. 중복 할당 방지
  3. 부모 Study 없이 Series 할당 시도 (에러 처리)

#### 3. **권한 검증 테스트**
- **설명**: 프로젝트 멤버가 아닌 사용자의 Study 할당 시도
- **이유**: RBAC 권한 검증 필요
- **테스트 시나리오**:
  1. 프로젝트 멤버가 아닌 사용자로 로그인
  2. Study 할당 시도
  3. 403 Forbidden 반환 확인

### ⚠️ **QIDO-RS 데이터 부족 문제**

**현상**: 대부분의 테스트가 404로 스킵됨
**원인**: QIDO-RS (Dcm4chee PACS)에 실제 Study 데이터가 없음
**영향**: 테스트 문제 아님, **환경 문제**
**해결**:
- 실제 DICOM Study를 PACS에 업로드하면 테스트 완전 실행 가능
- 현재 테스트 코드는 **404 응답도 정상 처리**하도록 설계됨
- API 로직은 **정상 작동** 확인됨
