# 기술 분석

## 🔍 문제의 근본 원인

### 1. sqlx의 타입 매핑 메커니즘

sqlx는 Rust의 타입 시스템을 활용하여 DB 쿼리 결과를 구조체로 매핑합니다.

#### `query_as!` vs `query_as::<_, T>`

**`query_as!` (컴파일 타임 체크)**:
```rust
// ✅ 컴파일 타임에 DB 스키마 체크
let annotation = sqlx::query_as!(
    Annotation,
    "SELECT * FROM annotation_annotation WHERE id = $1",
    id
)
.fetch_optional(&pool)
.await?;
```

**장점**:
- 컴파일 타임에 필드 불일치 감지
- 타입 안정성 보장
- IDE 자동완성 지원

**단점**:
- 빌드 시 DB 연결 필요
- 동적 쿼리 작성 어려움

---

**`query_as::<_, T>` (런타임 체크)**:
```rust
// ⚠️ 런타임에 매핑 시도
let annotation = sqlx::query_as::<_, Annotation>(
    "SELECT * FROM annotation_annotation WHERE id = $1"
)
.bind(id)
.fetch_optional(&pool)
.await?;
```

**장점**:
- 빌드 시 DB 연결 불필요
- 동적 쿼리 작성 가능

**단점**:
- 런타임 에러 발생 가능
- 필드 불일치 시 `MissingColumn` 에러

---

### 2. 현재 코드베이스의 선택

**사용 중**: `query_as::<_, T>` (런타임 체크)

**이유**:
- 빌드 파이프라인 단순화
- CI/CD에서 DB 연결 불필요
- 동적 쿼리 작성 유연성

**트레이드오프**:
- 필드 불일치 시 런타임 에러 발생
- 개발자가 수동으로 필드 일치 확인 필요

## 🐛 에러 발생 메커니즘

### 1. Entity 구조체
```rust
#[derive(Debug, Clone, Serialize, Deserialize, FromRow)]
pub struct Annotation {
    pub id: i32,
    pub project_id: i32,
    pub user_id: i32,
    pub study_uid: String,
    pub series_uid: String,
    pub instance_uid: Option<String>,
    pub tool_name: String,
    pub tool_version: String,
    pub data: serde_json::Value,
    pub is_shared: bool,
    
    // ✅ 새로 추가된 필드
    pub snapshot_image_key: Option<String>,
    pub snapshot_status: Option<SnapshotUploadStatus>,
    pub snapshot_uploaded_at: Option<DateTime<Utc>>,
    
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
    pub version: i32,
    pub viewer_software: Option<String>,
    pub description: Option<String>,
    pub measurement_values: Option<serde_json::Value>,
    pub label: Option<String>,
}
```

### 2. 기존 SELECT 쿼리
```sql
SELECT id, project_id, user_id, study_uid, series_uid, instance_uid,
       tool_name, tool_version, data, is_shared, created_at, updated_at,
       viewer_software, description, measurement_values, label, version
FROM annotation_annotation
WHERE id = $1
```

**반환 컬럼**: 17개  
**Entity 필드**: 20개 (snapshot 관련 3개 추가)

### 3. sqlx 매핑 시도
```rust
// sqlx가 쿼리 결과를 Annotation으로 매핑 시도
let annotation = sqlx::query_as::<_, Annotation>(query)
    .bind(id)
    .fetch_optional(&pool)
    .await?;
```

**매핑 과정**:
1. 쿼리 실행 → 17개 컬럼 반환
2. `FromRow` trait 사용하여 Annotation으로 변환 시도
3. `snapshot_image_key` 필드를 찾을 수 없음
4. **에러 발생**: `MissingColumn("snapshot_image_key")`

### 4. 에러 전파
```
Repository Error
    ↓
Service Error
    ↓
Use Case Error
    ↓
Controller Error
    ↓
HTTP 500 Internal Server Error
```

## 🔧 해결 방법의 원리

### 1. 필드 순서 일치

**Entity 필드 순서**:
```rust
pub struct Annotation {
    pub id: i32,
    pub project_id: i32,
    // ... 기본 필드들
    pub is_shared: bool,
    pub snapshot_image_key: Option<String>,      // ← 여기
    pub snapshot_status: Option<SnapshotUploadStatus>,
    pub snapshot_uploaded_at: Option<DateTime<Utc>>,
    pub created_at: DateTime<Utc>,
    // ... 나머지 필드들
}
```

**SELECT 쿼리 순서**:
```sql
SELECT id, project_id, user_id, study_uid, series_uid, instance_uid,
       tool_name, tool_version, data, is_shared,
       snapshot_image_key, snapshot_status, snapshot_uploaded_at,  -- ← 여기
       created_at, updated_at, version,
       viewer_software, description, measurement_values, label
FROM annotation_annotation
```

**중요**: 순서가 정확히 일치해야 함!

### 2. FromRow Derive Macro

`#[derive(FromRow)]`는 다음과 같이 동작:

```rust
// sqlx가 자동 생성하는 코드 (개념적)
impl FromRow for Annotation {
    fn from_row(row: &Row) -> Result<Self, Error> {
        Ok(Annotation {
            id: row.try_get("id")?,
            project_id: row.try_get("project_id")?,
            // ...
            snapshot_image_key: row.try_get("snapshot_image_key")?,  // ← 이 부분이 실패했었음
            snapshot_status: row.try_get("snapshot_status")?,
            snapshot_uploaded_at: row.try_get("snapshot_uploaded_at")?,
            // ...
        })
    }
}
```

**수정 후**:
- 모든 필드가 쿼리 결과에 존재
- `try_get()` 성공
- Annotation 인스턴스 생성 성공

async fn test_annotation_crud(pool: PgPool) {
    let repo = AnnotationRepositoryImpl::new(pool);

    // 조회

    assert!(deleted);
}
